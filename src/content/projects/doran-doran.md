## 1. 프로젝트 개요

### 서비스 소개

![도란도란 서비스](/images/projects/doran-doran/service.jpg)

**도란도란**은 잠들어 있던 우리 설화 데이터를 아이의 문해력 수준에 맞는 전래동화로 다시 써 주는 AI 동화 생성 플랫폼이다. 국립민속박물관 · 한국학중앙연구원의 설화 원전과 국립국어원의 어휘 등급화 연구를 바탕으로, **진단 → 생성 → 학습**을 하나의 흐름으로 잇는다.

- 배치고사로 아이의 현재 문해력을 **0–10세를 아우르는 20단계** 중 하나로 산정하고, 그 단계의 어휘 · 문장 · 받침 · 의성어 기준에 맞춰 설화를 실시간으로 재구성한다.
- 생성형 AI로 동화를 "만드는" 것보다, **아이 수준에 맞는 언어를 지키면서 원전의 인물 · 사건 · 교훈을 유지하는 것**을 핵심 과제로 잡았다.
- 동화마다 장면 삽화와 낭독 음성, 연계 퀴즈를 함께 만들고, 퀴즈 결과에 따라 다음 동화의 단계가 조정된다.

## 2. 프로젝트 기획

### 2.1 문제 정의

![문해력 위기는 이미 시작됐습니다](/images/projects/doran-doran/ppt-problem.jpg)

**① 문해력 위기는 이미 시작됐다**

- OECD 국제성인역량조사(PIAAC, 2024)에서 한국 성인 문해력 평균은 **249점**으로 OECD 평균(260점)보다 낮고, 최근 10년간 하락 폭은 참여국 중 1위였다.
- 성인의 **58.8%** 가 한 달간 책을 한 페이지도 읽지 않았고(국립국어원, 2024), 초등 6학년 **3명 중 1명**이 책을 거의 읽지 않는다(한국교육과정평가원, 2024).
- 교원의 **95.1%** 가 학생들의 문해력 저하를 체감하지만(한국교원단체총연합회, 2024), 전국 17개 시도교육청 중 문해력 진단을 시행하는 곳은 **1곳**뿐이다.

<a href="/images/projects/doran-doran/oecd-literacy.png"><img src="/images/projects/doran-doran/oecd-literacy.png" alt="국가별 성인 문해력 평균 점수" style="max-width:420px;width:100%;" /></a>

**② 그 뿌리는 어린 시절에 있다**

디지털 매체 과노출로 인한 아동 문해력 저하는 더 이상 외면할 수 없는 사회 문제지만, 체계적인 조기 대응 체계는 아직 없다. 한편 국립민속박물관이 정리한 800여 편의 설화 데이터는 디지털 세대에게 닿지 못한 채 잠들어 있었다.

도란도란은 이 두 가지를 하나로 잇는다. **아이의 문해력 수준을 먼저 진단하고, 그 수준에 맞춘 언어로 우리 설화를 다시 들려주고, 읽은 내용을 퀴즈로 확인해 다음 단계로 이어가는 것**을 목표로 잡았다.

### 2.2 타깃 사용자

| 구분 | 사용자 | 필요한 것 | 도란도란이 주는 것 |
|------|------|------|------|
| 가정 (B2C) | 0–10세 아이를 둔 부모, 맞벌이 가정 | 아이 수준에 맞는 읽을거리, 짧은 시간의 교육 루틴 | 단계 맞춤 동화, 낭독 음성, 부모님 성장 기록 |
| 기관 (B2B) | 유치원 · 어린이집 · 초등학교 교사 | 동화 읽기 수업 자료, 반 아이들의 수준별 관리 | 교사용 LMS, 반 단위 동화 생성 · 배포 |

- **7세 미만**은 부모와 함께 읽는 루틴으로 정서적 유대를 쌓고, **7세 이상**은 퀴즈 · 레벨업 구조로 스스로 읽는 습관을 만든다.
- 유치원은 학원과 달리 학습 관리 도구가 없어 동화 읽기 같은 일상 업무를 교사가 직접 감당한다. 기관용 LMS는 이 현장 문제에서 출발했다.

### 2.3 서비스 방향

![진단 → 생성 → 학습](/images/projects/doran-doran/service-flow.png)

| 단계 | 하는 일 |
|:---:|------|
| **진단** | 나이와 발달 수준을 기준으로 배치고사를 치러 아이의 현재 단계를 20단계 중 하나로 산정한다 |
| **생성** | 산정한 단계에 맞춰 AI가 설화 원전을 실시간으로 재구성해 동화를 만든다 |
| **학습** | 동화 내용과 연계된 퀴즈로 이해도를 확인하고, 결과에 따라 다음 동화의 난이도를 조정한다 |

### 2.4 차별점

![기존 서비스와의 비교](/images/projects/doran-doran/ppt-comparison.jpg)

기존 AI 동화 앱은 아이의 문해력을 측정하지 않거나, 측정하더라도 전통문화 데이터와 학습 연계를 함께 갖추지 못했다. 도란도란의 차별점은 "문해력"이라는 주제보다 **공공기관이 검증한 설화 원전을 생성의 뼈대로 쓴다는 것**에 있다.

### 2.5 비즈니스 모델

![개발 로드맵과 수익 구조](/images/projects/doran-doran/ppt-roadmap-bm.jpg)

| 구분 | 대상 | 방식 |
|------|------|------|
| B2C | 가정 | **크레딧** 방식으로 동화를 생성한다. 원하는 이야기는 **실물 동화책(POD)** 으로 주문할 수 있다 |
| B2B | 유치원 · 초등 기관 | 기관 단위 **LMS 구독**. 이후 해외 한국어 교육기관까지 확장한다 |

- 가정은 매달 같은 금액을 내는 구독 대신, 필요한 만큼 쓰는 크레딧으로 시작 부담을 낮췄다. 구독은 꾸준히 반을 운영하는 기관용 LMS에만 적용한다.
- 실물 동화책은 선물용으로 포지셔닝하고 꾸미기 옵션을 다양하게 둔다. 원고료가 들지 않아 가격 경쟁력이 있다.
- **B2B2C 시나리오**: 유치원 그림 수업에서 아이들이 그린 그림으로 교사가 동화를 만들고, LMS로 부모에게 보낸다. 아이는 집에서 앱으로 다시 읽고, 가정은 크레딧이나 실물 책으로 이어진다. 유치원 영업이 곧 매출이자 그 반 부모를 데려오는 마케팅이 되고, "유치원에서 쓰는 제품"이라는 신뢰가 프리미엄이 된다.
- 마케팅 메시지는 부모에게는 "좋은 부모가 되는 것", 교사에게는 "좋은 선생님이 되는 것"이다.

**기대 효과**

| 구분 | 내용 |
|------|------|
| 정량 | 하루 10–15분 개인화 동화 읽기로 맞벌이 가정의 교육 부담을 덜고, 9.9조 원 규모의 에듀테크 시장에서 차별화한다 |
| 정성 | 7세 미만은 부모와 함께 읽는 루틴으로 정서적 유대를, 7세 이상은 퀴즈 · 레벨업으로 능동적인 독서 습관을 만든다 |

### 2.6 프로젝트 관리

**① 협업 방식**

세 명이 기획 · 데이터, 백엔드, 프론트엔드를 하나씩 맡아 WBS나 요구사항 정의서 없이 **애자일하게** 진행했다. 대회 일정을 마일스톤으로 두고, 각 마일스톤마다 동작하는 버전을 만든 뒤 피드백을 받아 다음 버전에 반영하는 방식이다.

- **MVP → POC**: 공모전 버전(MVP)으로 진단 → 생성 → 학습의 흐름을 먼저 완성하고, 창업경진대회 버전(POC)에서 생성 품질 · 속도 · 안정성을 실제 서비스 수준으로 끌어올렸다.
- **외부 피드백 반영**: 사업 컨설팅에서 받은 "고객 검증이 먼저"라는 권고와, IR 컨설팅에서 확인한 태블릿 사용 환경을 바로 다음 버전의 방향으로 삼았다.
- **결정 기록**: 모델 교체나 생성 구조 변경처럼 결과에 영향을 주는 결정은 실험 조건과 결과, 채택 이유를 날짜별 문서로 남겼다. 커밋은 `feat:` · `fix:` · `docs:` · `perf:`로 목적을 구분했다.

**② 역할 분담**

| 영역 | 담당 업무 |

| BACKEND | API 서버 구현, 생성 파이프라인 · DB 설계, 배포 |
| FRONTEND | 웹 UI 구현, 백엔드 API 연동, 태블릿 화면 전환 |

## 3. 프로젝트 상세

### 3.1 시스템 아키텍처

<a href="/images/projects/doran-doran/diagram-architecture.png"><img src="/images/projects/doran-doran/diagram-architecture.png" alt="도란도란 시스템 아키텍처" /></a>

- 생성 요청은 DB 작업 큐에 접수되고 서버 내부 실행기가 처리한다. 동화 한 권을 만드는 데 시간이 걸리기 때문에, 사용자는 다른 화면으로 이동해도 진행 상황을 이어서 확인할 수 있다.
- 노드가 끝날 때마다 결과(후보 본문, 컷별 이미지, 장별 음성)를 저장해 두고, 작업이 중간에 끊기면 **마지막으로 저장된 지점부터 이어서** 생성한다. 유료 호출을 처음부터 다시 하지 않는다.
- 무거운 형태소 분석(Kiwi)은 웹 서버 밖의 GitHub Actions 배치로 분리했다.

| Vector DB | Qdrant (`folktales_v1` 원전, `vocab_grade_v1` 어휘) |

### 3.2 데이터

![문해력 맞춤 생성을 만드는 두 데이터 축](/images/projects/doran-doran/ppt-data-axes.jpg)

어휘는 **난이도**를, 설화는 **이야기의 뼈대**를 제어한다. 두 데이터를 단계별 생성 조건으로 연결하는 것이 도란도란 데이터 설계의 출발점이다.

#### 3.2.1 데이터 출처

| 데이터 | 제공 기관 | 규모 | 활용 |
|------|------|------|------|
| 한국민속문학사전 설화편 | 국립민속박물관 (2013) | 표제어 889개 | 동화의 원전. 줄거리와 핵심 화소를 생성 근거로 제공 |
| 국어 기초어휘 선정 및 어휘 등급화 연구 | 국립국어원 (2023) | 1–5등급 어휘 40,000개 | 단계별 사용 어휘 범위 제어 |
| 한국민족문화대백과사전 | 한국학중앙연구원 | 54편 | 원전 확장 (POC) |
| 한국민속문학사전 「설화 2」 | 국립민속박물관 | 55편 | 원전 확장 (POC) |

#### 3.3.2 생성 파이프라인 (LangGraph)

MVP는 모델 호출 · 검색 · 이미지 작업이 하나의 흐름에 얽혀 있어, 무엇을 고쳐야 품질이 좋아지는지 측정하기 어려웠다. POC에서 생성 과정을 **LangGraph 노드 단위로 다시 설계**하고, 노드마다 시간과 토큰을 기록했다.

<a href="/images/projects/doran-doran/diagram-pipeline.png"><img src="/images/projects/doran-doran/diagram-pipeline.png" alt="도란도란 생성 파이프라인" /></a>

| 단계 | 하는 일 |
|------|------|
| **원전 · 어휘 검색** | 아이의 나이와 주제에 맞는 원전을 검색하고, 단계에 허용된 어휘 등급 안에서 예시 어휘를 고른다 |
| **5장면 설계** | 장면마다 상황, 인물의 이유와 행동, 그 행동이 만든 직접적인 변화, 다음 장면으로 넘길 상태, 그림으로 볼 순간을 먼저 정한다 |
| **두 후보 집필** | 같은 설계 · 원전 · 어휘로 완성본 두 편을 병렬로 쓴다. 단계별 언어 지침을 모두 적용한다 |
| **후보 선택** | 인과 정합성과 단계 적합성으로 비교해 더 나은 한 편을 고른다 (3.3.5) |
| **퀴즈 · 삽화 · 음성** | 선택된 본문 하나로 세 작업을 병렬로 실행하고, 모두 끝나면 조립한다 |

장면 설계는 "다음 장면으로 넘어갈 때 무엇이 남는가"를 구조로 강제한다. 인물마다 위치 · 상태 · 알고 있는 것 · 가진 것을 다음 장면으로 넘기게 해, 인물이 모르는 사실을 갑자기 아는 식의 인과 공백을 줄였다.

    graph.add_node(name, checkpoint_node(checkpoint, name, node))

    else "plan_relaxed" if is_relaxed(state["request"]) else "plan",
    ["plan_original", "plan_relaxed", "plan"])

    # 같은 원전/어휘 표본/개인화로 독립된 전체 동화 두 편을 병렬 작성한다
    return [Send("write_candidate", {**state, "candidate_id": cid}) for cid in ("A", "B")]

graph.add_edge("assets", "quizzes")

graph.add_edge("assets", "narration")
graph.add_edge(["quizzes", "illustrations", "narration"], "assemble")   # 세 분기 합류

class Beat(StrictModel):
    actor_id: str = Field(pattern=r'^c[1-5]$')
    reason: str = Field(min_length=1, max_length=100)
    action: str = Field(min_length=1, max_length=140)
    direct_effect: DirectEffect | None   # 이 행동이 실제로 만든 변화 (before → after)
    change: Change | None                # 생각이나 행동 방향이 실제로 바뀔 때만. 채우기 위한 교훈은 만들지 않는다

class ContinuityFact(StrictModel):
    actor_id: str = Field(pattern=r'^c[1-5]$')
    aspect: Literal['location', 'condition', 'knowledge', 'possession']
    value: str = Field(min_length=1, max_length=100)

class Chapter(StrictModel):
    page_number: int = Field(ge=1, le=5)

#### 3.3.3 RAG: 원전과 어휘를 검색으로 공급

MVP는 원전과 어휘를 고정 목록에서 골랐다. POC에서는 두 데이터를 모두 Qdrant 검색으로 공급하도록 바꿨다.

**① 원전 RAG**

- 아이가 좋아하는 것 · 오늘 있었던 일 · 선택한 주제를 질의로 임베딩해 Qdrant에서 원전 후보를 찾는다. 아이의 나이에 허용된 원전, 현재 데이터셋 버전, 같은 임베딩 모델로 적재된 원전만 검색 전에 필터로 거른다.
- 후보는 Gemini가 "아이의 관심사를 사건과 해결에 쓸 수 있는지, 감정적으로 어울리는지"로 다시 정렬한다. 옛 이야기 모드는 후보 원전의 실제 줄거리가 선택한 주제와 맞는지까지 확인하고, 맞지 않는 원전은 집필 전에 제외한다.
- **최근에 읽은 원전은 감점**한다. 직전 원전은 점수의 0.2배, 그 전 원전은 0.6배로 낮춰 같은 이야기가 반복되지 않게 했다. 재정렬 모델은 순위만 돌려주고, 감점은 그 순위 점수에 코드로 적용하기 때문에 모델이 감점을 되돌릴 수 없다.
- Qdrant가 응답하지 않으면 로컬 목록의 키워드 검색으로 낮춰 생성을 이어가고, 어떤 경로로 검색했는지를 결과에 남긴다.

**② 어휘 RAG**

- 아이의 단계에 허용된 어휘 등급 안에서만 검색해 최대 8개의 예시 어휘를 고른다.
- 관심사 · 오늘의 경험 · 원전 주제를 **하나로 합치지 않고 각각 임베딩**해 검색한 뒤 합친다. 하나로 합쳐 임베딩하면 벡터가 흐려지기 때문이다. 상위 후보 풀에서 무작위로 골라 매번 같은 조합이 나오지 않게 한다.
- 예시 어휘는 "참고일 뿐 반드시 써야 하는 목록이 아니다"라고 프롬프트에 명시한다. 소리 중심인 1–2단계와 기본 명사 단계는 의미 검색으로 범위를 넓히지 않고 별도로 좁혀 둔 어휘 풀을 그대로 써서, 발달 단계의 안전장치를 검색이 무너뜨리지 않게 했다.

def recent_source_weights(request, known_ids):
    """최근 두 편의 순서를 유지해 감점한다. 같은 원전은 가장 강한 감점 한 번만 쓴다."""
    defaults = (("RECENT_SOURCE_LATEST_WEIGHT", 0.2), ("RECENT_SOURCE_PREVIOUS_WEIGHT", 0.6))
    weights = {}
    for source_id, (name, default) in zip(request.get("_recent_source_ids", [])[:2], defaults):
        if source_id in known_ids:
            weights[source_id] = min(weights.get(source_id, 1.0), weight_from_env(name, default))
    return weights


def weighted_score(score, weight):
    # 코사인 유사도가 음수일 때 곱하면 오히려 점수가 올라간다. 음수는 나누어 낮춘다.
    return score * weight if score >= 0 else score / weight


# 재정렬 LLM은 순위만 반환한다. 없는 적합도 점수를 만들지 않고 1/순위에 감점을 적용한다.
scores = {key: 1.0 / rank for rank, key in enumerate(ranked, 1)}
candidates.sort(key=lambda row: (
    -weighted_score(scores[row["source_id"]], weights.get(row["source_id"], 1.0)),
    -weights.get(row["source_id"], 1.0),       # 동점이면 덜 최근에 쓴 원전 우선
))

def search_vocab(request, source, level, n=8, *, theme_field="subject"):
    config = get_level_config(int(level))
    grades = config.get("vocab_grade")
    # 소리 중심 단계·기본 명사 단계는 의미 검색으로 넓히지 않는다 (발달 단계 안전장치)
    if not grades or config.get("vocab_scope") == "basic_noun":
        return sample_vocab(int(level), n=n), "random_scope_excluded"

    # 관심사 / 오늘의 경험 / 원전 주제를 각각 임베딩한다. 하나로 합치면 벡터가 흐려진다.
    queries = [source.get(theme_field)] if request.get("mode") == "original" \
        else [request.get("favorite"), request.get("today_event"), source.get(theme_field)]
    try:
        pool, seen = [], set()
        for query_text in queries:
            for point in _search_one(query_text, grades, embedding_model, _POOL_LIMIT):
                word = point.get("payload", {}).get("어휘")
                if word and word not in seen:
                    seen.add(word)
                    pool.append(word)
    except (ProviderError, KeyError, TypeError):
        return sample_vocab(int(level), n=n), "qdrant_unavailable_random_fallback"

    # 순위 그대로 쓰지 않고 상위 풀에서 무작위로 골라 매번 같은 조합이 나오지 않게 한다
    return (pool, "qdrant") if len(pool) <= n else (random.sample(pool, n), "qdrant")

#### 3.3.4 이야기 모드

같은 20단계 언어 지침을 공유하면서, 원전을 얼마나 지킬지에 따라 경로를 나눴다. 원전 보존과 개인화는 요구가 서로 충돌하기 때문에, 하나의 프롬프트로 둘 다 만족시키려 하지 않고 **그래프의 노드 경로 자체를 분리**했다.

| 모드 | 입력 | 원전 사용 | 개인화 |
|------|------|------|------|
| 옛 이야기 | 연령별 주제 카드 | 인물 · 핵심 사건 · 해결 · 결말을 그대로 유지 | 넣지 않음 |
| 나만의 이야기 | 이름 · 좋아하는 것 · 주제 · 오늘 있었던 일 | 핵심 갈등과 주제를 새 이야기로 각색 | 좋아하는 소재를 사건과 해결에 활용 |
| 가볍게 읽기 | 나만의 이야기와 같음 | 각색 | 단계 숫자로 난도를 올리지 않고 편하게 읽는 동화 |
| 내 그림 이야기 | 아이가 그린 그림 | 필요하면 어울리는 원전을 참고로 연결 | 그림 속 인물과 아이가 원하는 사건을 이야기로 |

- 옛 이야기 모드는 "원전을 고른 이유(주제)"를 새 사건을 넣으라는 지시로 쓰지 않는다. 주제에 맞추려고 인물 · 시대 · 해결 · 결말을 바꾸지 않고, 원전을 안전하게 보존할 수 없으면 새 줄거리로 위장하지 않는다.
- 나만의 이야기 모드의 주제는 분위기를 가볍게 참고하는 선택 사항이다. 원전 교훈과 함께 달성할 두 번째 목표로 만들지 않고, 훈계로 마무리하지 않는다.
- 내 그림 이야기는 그림을 비공개 저장소에 보관하고, 그림 속 인물과 아이가 원하는 사건을 먼저 해석해 확인받은 뒤 동화를 만든다.

#### 3.3.5 생성 검수: 서비스는 후보 선택, 실험은 결과 검증

![AI 생성 · 검수](/images/projects/doran-doran/ppt-generation-qa.jpg)

LLM으로 동화를 만들면 결과의 편차가 크고, 높은 단계일수록 인과가 끊기는 문제가 있었다. 그렇다고 점수를 매겨 기준 미달을 계속 재생성하면 시간과 비용이 늘어난다. 그래서 **실서비스에서는 더 나은 후보를 고르는 것**, **사후 실험에서는 단계별 차이를 수치로 확인하는 것**으로 역할을 나눴다.

**① 실서비스: 두 후보 중 더 나은 한 편을 고른다**

1. 같은 단계 · 원전 · 장면 설계 · 어휘 예시로 완성본 두 편을 병렬로 쓴다.
2. JSON 형식이나 필수 필드 같은 **구조 오류만** 후보당 최대 1회 다시 생성한다. 내용이 마음에 들지 않는다는 이유로는 재생성하지 않는다.
3. 두 후보가 모두 유효하면 Gemini가 실제 본문만 읽고 **인과 정합성(coherence)** 과 **단계 적합성(level_fit)** 을 0–4점으로 평가한다. 단계를 크게 벗어난 후보를 먼저 피하고, 그 안에서 인과 점수가 높은 쪽을 고른다.
4. 두 점수 모두 3점 이상이면 `selected`, 아니면 `selected_with_concerns`로 표시한다. 검증 호출이 실패하면 유효한 본문은 보존하되 검증을 통과했다고 표시하지 않는다.

기본 AI 호출은 장면 설계 1회, 본문 2회, 선택 1회로 4회다. 집필 · 선택 모델은 여러 구성을 같은 조건으로 비교한 뒤 **Gemini 3.8 Flash(low)** 로 정했다. 품질과 속도를 함께 맞춘 구성이다.

평가 지침은 "따뜻한 결말이나 '지혜로 해결했다'는 선언만으로 높은 점수를 주지 않는다", "1–2단계는 갈등 · 교훈 · 인과를 요구하지 않고 소리와 감각 장면의 연결로 판단한다"처럼 동화 특성에 맞췄다. 원전 충실도나 문장의 화려함은 가산점이 아니다.

**② 사후 실험: 최종 결과가 실제로 단계별로 다른가**

생성된 최종 동화를 Kiwi로 형태소 분석하고 어휘를 국립국어원 Grade 1 · 2 · 3으로 분류해 단계별 분포를 비교한다(4.1). Grade 비율은 실시간 통과 · 탈락 조건으로 쓰지 않는다.

#### 3.3.6 퀴즈 · 삽화 · 낭독

선택된 본문 하나로 세 작업을 병렬로 실행한다. 각 작업은 서로 다른 상태 키에 결과를 써서 덮어쓰지 않는다.

| 작업 | 구현 |
|------|------|
| 연계 퀴즈 | 10단계 이상은 7문항. 10–13단계는 어휘 · 사실 · 감정, 14–16단계는 어휘 추론 · 인과 · 순서, 17–18단계는 심리 · 동기, 19–20단계는 주제 · 표현 · 서사 구조를 묻는다. 씨앗 · 새싹 단계는 부모님 체크리스트로 확인한다 |
| 삽화 | 캐릭터 시트를 먼저 만들고 그 시트를 참조해 표지와 5장면을 그려, 장면마다 인물 외형이 달라지는 문제를 막았다. 기본 모델은 GPT Image 2.5다 |
| 낭독 음성 | Gemini TTS로 5개 장을 동시에 생성해 MP3로 저장하고, 구간별 시간표를 함께 저장해 읽는 부분을 화면에 표시한다 |

- 퀴즈 화면에는 동화 본문이 함께 표시되지 않는다. 그래서 문항마다 풀이에 필요한 본문 문장을 원문 그대로 발췌해 넣게 하고, "동화 전체를 가리고 발췌 · 질문 · 보기만 읽어서 풀 수 있는지" 출력 전에 스스로 점검하도록 지침을 만들었다.
- 퀴즈를 만점으로 풀면 원전 인물을 바탕으로 만든 스티커를 한 장 받아 스티커북에 모은다.

단계별 동화 5편씩 생성해 Kiwi 형태소 분석 후 Grade 2+3 어휘 비율과 총 분석 어휘 수를 비교했다.

| 단계 | L1 | L5 | L10 | L15 | L20 |
|------|:---:|:---:|:---:|:---:|:---:|

### 4.4 회고 · 로드맵

- **"문해력"보다 "설화 원전"이 차별점이었다.** 처음에는 문해력 위기를 앞세웠지만, 컨설팅을 거치며 경쟁 서비스와 진짜로 갈리는 지점은 공공기관이 검증한 원전을 생성의 뼈대로 쓴다는 데 있다는 걸 정리하게 됐다. 그래서 데이터 작업의 중심도 원전을 늘리고, 원전과 다른 내용이 만들어지지 않게 검색으로 공급하는 쪽으로 옮겨 갔다.
- **품질은 점수가 아니라 구조로 관리했다.** 생성 결과의 편차를 재생성 루프로 잡으려 하지 않고, 장면 설계로 인과를 먼저 고정한 뒤 두 후보 중 나은 쪽을 고르는 구조로 바꿨다. 검증이 실패하면 통과로 표시하지 않고, 실시간 판단과 사후 실험의 역할도 분리했다.
- **비어 있는 기준은 직접 설계해야 했다.** 국립국어원 어휘 등급은 만 4세 이상부터라 영아기 기준이 없었다. K-DST · 누리과정 · 한글또박또박을 교차해 20단계를 만들고 의성어 · 의태어로 그 구간을 채운 것이, 0세부터 쓸 수 있는 서비스의 전제가 됐다.
- **다음 과제는 고객 검증이다.** 사업 컨설팅에서 "문해력이 정말 핵심 니즈인지 가정에서 먼저 확인하라"는 권고를 받았다. 출시 후 맘카페와 유치원 직접 방문으로 실제 사용 반응을 확인할 계획이다.

| 단계 | 시기 | 내용 |
|------|------|------|
| Phase 1 · 멀티모달 코어 엔진 | 단기 · 1–3개월 | 문맥 맞춤형 이미지 생성 · 고품질 TTS로 시청각 기능을 완성하고, 체류 시간 · 완독률 데이터를 확보 |
| Phase 2 · 데이터 피드백 루프 & B2B/B2G | 중기 · 4–7개월 | 오답 분석 기반 맞춤 솔루션으로 고도화하고, 유치원 · 돌봄교실 · 다문화지원센터용 통합 관리 대시보드(LMS) 공급 |
| Phase 3 · 글로벌 확장 & 실물 BM 결합 | 장기 · 8–12개월 | 다국어 확장, 실물 동화책 출판 · 배송(POD), K-콘텐츠 수출과 한국어 교육 인프라 선점 |
