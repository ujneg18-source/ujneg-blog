## 1. 프로젝트 개요 및 기획 배경
환희(HWANHEE)는 현대인의 글쓰기 능력 향상과 가독성 높은 맞춤형 문장 개선을 돕기 위해 기획된 **LLM 기반 한국어 가독성 분석 및 자동 피드백 서비스**입니다. 단순한 문법 교정을 넘어, 독자의 배경지식과 어구의 복합성을 분석하여 최적의 대체 어휘와 간결한 문장 구조를 제시합니다.

### 기획 의도와 대상 유저
- **주요 대상**: 학술 논문, 에세이, 혹은 기사 및 기술 블로그를 정제된 어조로 작성하려는 라이터 및 엔지니어
- **핵심 목표**: 복잡하고 난해한 전문 용어 중심의 한국어 텍스트를 대상 독자 수준(초급/중급/고급)에 맞게 다분화된 AI 피드백으로 정제

## 2. 핵심 기능 및 RAG 아키텍처
LLM의 환각(Hallucination) 현상을 방지하고 고품질 문장 교정 알고리즘을 유지하기 위해 **검증된 언어학 사전 및 글쓰기 지침 텍스트 DB**를 RAG (Retrieval-Augmented Generation) 파이프라인으로 연결했습니다.

### RAG 파이프라인 작동 구조
1. **문서 청크 분할 및 파싱**: 사용자가 입력한 초안 텍스트를 문장 단위 및 의미 단락별로 토큰화 진행
2. **벡터 검색 (Vector Search)**: 텍스트의 어조와 어휘의 난이도를 인베딩 모델로 추출하여 가장 이상적인 첨삭 사례 DB와 매칭
3. **가이드라인 부스팅 생성**: 프롬프트 체인 구성을 통해 실시간 교정 이유와 대안 문장을 동시에 반환

## 3. 백엔드 시스템 설계와 트러블슈팅
본 서비스의 core 백엔드 엔진은 **Python 및 FastAPI** 프레임워크를 기반으로 비동기 스트리밍(SSE) 응답 처리를 지원하도록 설계되었습니다. LLM 생성 시간이 지존 monolithic 응답보다 길다는 UX 한계를 타파하는 데 중점을 두었습니다.

### 실시간 비동기 스트리밍 (SSE) 구현
- 기존 요청/응답 (HTTP Query) 대기 시간 최소화
- 토큰 생성 속도에 맞춰 UI 상에서 문장별 수정 피드백이 마트료시카처럼 즉각 렌더링되도록 WebSocket 및 SSE 프로토콜 최적화

### 트러블슈팅: 다중 동시 접속 시 LLM 호출 지연 및 락 문제
- **문제 현상**: 여러 사용자가 동시에 긴 장문을 요청할 때, 파이프라인에서 인메모리 임베딩 연산이 병목을 일으키며 FastAPI 워커 전체가 Timeout에 도달
- **해결 방안**: Heavy 연산 영역을 Celery 비동기 백그라운드 태스크로 분리하고, Redis 캐싱 레디스 키 조회를 통해 이미 판독된 동일 단락 구문의 경우 LLM API 재요청 없이 즉시 반환하도록 최적화 달성 (응답 시간 평균 65% 절감)

## 4. 프로젝트 프로젝트 회고 및 성향
팀 리드 및 백엔드 설계 담당자로서, LLM API 자체의 역량뿐 아니라 이를 둘러싼 시스템 파이프라인(RAG, 큐 매니징, 프롬프트 모듈화)이 최종 서비스 퀄리티의 80%를 결정짓는다는 것을 깊이 체감한 귀중한 프로젝트였습니다.
