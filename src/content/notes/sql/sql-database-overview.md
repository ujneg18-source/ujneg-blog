## 데이터베이스와 DBMS

**데이터베이스(Database)** 는 지속적으로 유지·관리해야 하는 데이터의 집합이다. 한 번 쓰고 버리는 값이 아니라 계속 보관하면서 꺼내 쓰는 데이터이므로 HDD·SSD 같은 영구 저장 장치에 저장한다.

**DBMS(Database Management System)** 는 이 데이터베이스를 관리해 주는 소프트웨어다. 데이터를 넣고, 바꾸고, 지우고, 찾는 요청을 받아 실제 저장소에 반영한다. MySQL, Oracle, MS-SQL, DB2가 대표적인 DBMS다.

두 용어는 자주 섞어 쓰지만 구분해 두면 이후 내용이 정리된다.

| 구분 | 가리키는 것 | 예 |
|---|---|---|
| 데이터베이스 | 저장된 데이터 자체 | 회원 정보, 주문 내역 |
| DBMS | 데이터베이스를 관리하는 프로그램 | MySQL, Oracle |

## 관계형 데이터베이스(RDB)

**관계형 데이터베이스(Relational Database)** 는 데이터를 행과 열로 이루어진 2차원 표 형식으로 관리한다. 관계 있는 여러 항목(열)을 묶어 하나의 데이터 집합으로 표현하고, 이 집합을 **관계(Relation)** 라고 부른다. 업무적으로 연관된 테이블끼리 관계를 맺어 데이터를 관리하는 것이 핵심이다.

| ID | 이름 | 나이 |
|---|---|---|
| A120 | 홍길동 | 20 |
| A121 | 이순신 | 24 |
| A122 | 강감찬 | 23 |

위 표 하나가 **테이블**이고, 가로 한 줄이 **행**, 세로 한 칸이 **열**이다. 같은 대상을 여러 이름으로 부르기 때문에 용어를 짝지어 기억해 두었다.

| 용어 | 다른 이름 | 의미 |
|---|---|---|
| 테이블(Table) | 관계(Relation) | 데이터를 저장하는 단위. 관리하려는 데이터 단위별로 만든다 |
| 행(Row) | 레코드(Record), 튜플(Tuple) | 데이터 하나 |
| 열(Column) | 속성(Attribute) | 데이터를 구성하는 속성 |

### Entity와 Table

설계 단계에서는 **Entity**라는 말을 쓴다. Entity는 시스템이 독립적으로 관리하고 싶은 데이터의 단위이고, **Table**은 그 Entity를 실제 데이터베이스에 표현한 형태다. 예를 들어 "직원"이라는 Entity를 정하면 `emp` 테이블로 만든다.

## DBMS 처리 흐름: Client–Server 구조

DBMS는 **서버 프로그램**이다. 네트워크로 연결된 클라이언트가 요청을 보내면 서버가 처리하고 결과를 돌려준다.

1. 클라이언트가 SQL문으로 요청한다. (삽입, 삭제, 수정, 조회)
2. DBMS가 요청 내용을 데이터베이스에 처리한다.
3. 처리 결과를 클라이언트에게 보낸다. 조회 결과는 테이블 형태로 돌려준다.

MySQL Workbench나 Python 코드가 클라이언트 역할을 하고, MySQL 서버가 DBMS 역할을 한다. 그래서 Workbench에서 쿼리를 실행하든 Python에서 실행하든 서버에 전달되는 것은 같은 SQL문이다. Python 연동은 시리즈 마지막 글에서 다룬다.

## SQL과 명령어 분류

**SQL(Structured Query Language)** 은 데이터베이스에 데이터를 질의·등록·수정·삭제하도록 요청하는 표준 언어다. 하는 일에 따라 세 가지로 나눈다.

| 분류 | 이름 | 명령어 | 하는 일 |
|---|---|---|---|
| DML | Data Manipulation Language | `INSERT`, `UPDATE`, `DELETE`, `SELECT` | 테이블의 데이터를 추가·수정·삭제·조회한다 |
| DDL | Data Definition Language | `CREATE`, `ALTER`, `DROP`, `TRUNCATE` | 데이터베이스, 테이블, 뷰, 인덱스 같은 객체(스키마)를 만들고 바꾸고 지운다 |
| DCL | Data Control Language | `GRANT`, `REVOKE` | 사용자에게 권한을 주거나 회수한다 |

분류를 나누는 이유는 **되돌릴 수 있는지**가 다르기 때문이다.

- **DML**은 트랜잭션이 발생한다. 실행 결과가 임시로 적용되고, `COMMIT`으로 확정하거나 `ROLLBACK`으로 취소할 수 있다.
- **DDL**은 트랜잭션이 발생하지 않는다. 실행하면 바로 반영되고 `ROLLBACK`으로 되돌릴 수 없다. 테이블을 `DROP`하면 되돌릴 수 없다는 뜻이다.

> SELECT를 DML에 포함하는 분류와, 조회만 따로 **DQL(Data Query Language)** 로 나누는 분류가 있다. 수업 자료는 SELECT를 DML에 넣었고, PyMySQL 실습 노트에서는 SELECT를 DQL로 표기했다.

## SQL 작성 기본 규칙

### 주석

`01_DDL.sql` 첫머리에 정리한 주석 문법이다.

```sql
# 한줄 주석
-- 한줄 주석 (-- 다음에 공백이 있어야 한다)
/* block 주석 */
```

`--` 뒤에 공백을 넣지 않으면 주석으로 인식되지 않는다는 점을 메모해 두었다.

### 대소문자

- SQL 키워드, 테이블 이름, 컬럼 이름은 대소문자를 구분하지 않는다. `SELECT`와 `select`는 같다.
- 문자열 값은 작은따옴표(`'값'`)로 감싼다.

### MySQL Workbench 사용 팁

- 글꼴 변경: `Edit` → `Preferences` → `Fonts & Colors`
- 커서가 있는 SQL문 실행: `Ctrl + Enter` (macOS는 `Cmd + Enter`)

## 정리

- 데이터베이스는 데이터 집합이고, DBMS는 그것을 관리하는 서버 프로그램이다.
- 관계형 데이터베이스는 데이터를 테이블(행·열)로 관리하고, 테이블끼리 관계를 맺는다.
- SQL은 DDL(구조 정의), DML(데이터 조작), DCL(권한 제어)로 나뉜다.
- DML은 `COMMIT`/`ROLLBACK`으로 확정하거나 취소할 수 있지만, DDL은 실행 즉시 반영된다.
