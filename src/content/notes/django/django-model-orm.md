## ORM이란

ORM(Object Relational Mapping)은 파이썬 클래스와 DB 테이블을 짝지어 **SQL 없이** CRUD를 하게 해 준다.

| 파이썬 | 데이터베이스 |
|---|---|
| Model 클래스 | 테이블 |
| 클래스 변수(Field) | 컬럼 |
| 객체 하나 | 행 하나 |

| 장점 | 단점 |
|---|---|
| 업무 로직과 DB 로직 분리 | DBMS 고유 기능은 못 씀 |
| SQL을 직접 쓰지 않아 DBMS 종속성이 줄어듦(SQLite → MySQL 교체가 설정 변경만으로) | 복잡한 쿼리는 오히려 어려움 |

강의 자료의 당부는 "ORM을 쓰더라도 **어떤 SQL이 실행되는지** 알고 있어야 한다"였다. 아래 실습에서 `.query`로 SQL을 계속 찍어 보는 이유다.

## Model 정의

설문은 질문(`Question`) 하나에 보기(`Choice`) 여러 개가 달리는 1:N 구조다. 내 `models.py`는 필기를 주석으로 촘촘히 달아 두었다.

```python
from django.db import models

# 모델 클래스들을 정의 - Question(설문 질문), Choice(설문 보기)
## - Model을 상속
## - class이름: 단수형
## - class변수로 Field들을 정의. (Field - Table의 컬럼) 
###   - Field: 필드이름(컬럼이름, instance변수 이름) = Field객체(컬럼 설정)
## - primary key Field가 없으면 자동으로 생성
### - Field명: id, type: 양의 정수, 1씩 자동증가.
### - 특정 Field를 PK로 설정하려면 `XXXField(primary_key=True)` 로 설정

# Question Model class정의
class Question(models.Model):  # create table question (
    # 질문문장
    question_text = models.CharField(max_length=200) # question_text varchar(200)
    # 질문등록일시
    pub_date = models.DateTimeField(auto_now_add=True)  # pub_date datetime
    # auto_now_add=True : insert 시점의 일시를 자동으로 입력.
    
    def __str__(self):
        return f"{self.pk}. {self.question_text}"
        # self.pk : Primary Key Field의 값을 조회.

# Choice 모델 클래스
class Choice(models.Model):
    choice_text = models.CharField(max_length=200)
    vote = models.PositiveIntegerField(default=0)
    question = models.ForeignKey(
        Question,  # 참조 Model 클래스
        on_delete = models.CASCADE # 부모 데이터서 삭제되면 같이 삭제.
    )
    def __str__(self):
        return f'{self.pk}. {self.choice_text}'

# 모델 클래스를 최초 생성, 수정 한 경우 Database에 적용
#  1. python manage.py makemigrations  [app이름]
#                                       - app 이름을 주면 그 app에만 적용
#     - DB에 적용할 것들을 코드로 작성.
#  2. python manage.py migrate   # DB에 적용

# 테이블 이름: app이름_class이름 (polls_question)
```

| Field | 컬럼 | 비고 |
|---|---|---|
| `CharField(max_length=)` | varchar | `max_length` 필수 |
| `TextField` | text | 긴 글 |
| `IntegerField`, `PositiveIntegerField`, `FloatField` | 숫자 | |
| `DateTimeField`, `DateField` | 일시, 날짜 | `auto_now_add`(생성 시), `auto_now`(저장할 때마다) |
| `BooleanField` | 참/거짓 | |
| `FileField`, `ImageField` | 파일 경로 | `ImageField`는 pillow 필요 |
| `ForeignKey(부모, on_delete=)` | FK | 1:N, 자식 쪽에 선언 |

`__str__`은 객체를 출력할 때 보일 문자열이다. 아래 실행 결과의 `<Question: 1. 좋아하는 색은 무엇입니까?>`가 이 메서드의 결과다. 안 만들면 `<Question: Question object (1)>`로 나와서 무엇인지 알아보기 어렵다.

| 옵션 | 의미 |
|---|---|
| `null=True` | DB 컬럼이 NULL 허용 |
| `blank=True` | 폼 검증에서 빈 값 허용 |
| `default=` | 값을 안 주면 들어갈 기본값 |
| `unique=True` | 중복 금지 |
| `verbose_name=` | 폼의 label로 쓸 이름 |

`null`은 **DB**, `blank`는 **폼 검증** 설정이라는 점이 헷갈린다. 선택 입력인 생일 같은 필드는 둘 다 `True`로 둔다(6편의 `birthday`).

## makemigrations와 migrate

Model을 만들거나 고치면 두 단계로 DB에 반영한다.

```bash
python manage.py makemigrations   # 변경 내역을 migrations/0001_initial.py 같은 파일로 작성
python manage.py migrate          # 그 파일을 실제 DB에 적용
```

생성된 마이그레이션 파일은 "무엇을 바꿀지"를 파이썬 코드로 적어 둔 것이다(내 프로젝트의 파일).

```python
# Generated by Django 6.0.7 on 2026-07-24 06:23
...
        migrations.CreateModel(
            name='Question',
            fields=[
                ('id', models.BigAutoField(auto_created=True, primary_key=True, serialize=False, verbose_name='ID')),
                ('question_text', models.CharField(max_length=200)),
                ('pub_date', models.DateTimeField(auto_now_add=True)),
            ],
        ),
```

PK를 선언하지 않았으니 `id`가 자동으로 추가됐다. 실제로 실행될 SQL은 `sqlmigrate`로 볼 수 있다.

직접 실행(`python manage.py sqlmigrate polls 0001`, SQLite):

```text
BEGIN;
--
-- Create model Question
--
CREATE TABLE "polls_question" ("id" integer NOT NULL PRIMARY KEY AUTOINCREMENT, "question_text" varchar(200) NOT NULL, "pub_date" datetime NOT NULL);
--
-- Create model Choice
--
CREATE TABLE "polls_choice" ("id" integer NOT NULL PRIMARY KEY AUTOINCREMENT, "choice_text" varchar(200) NOT NULL, "vote" integer unsigned NOT NULL CHECK ("vote" >= 0), "question_id" bigint NOT NULL REFERENCES "polls_question" ("id") DEFERRABLE INITIALLY DEFERRED);
CREATE INDEX "polls_choice_question_id_c5b4b260" ON "polls_choice" ("question_id");
COMMIT;
```

- 테이블 이름이 `앱이름_모델이름`(`polls_question`)이다.
- `PositiveIntegerField`는 `CHECK ("vote" >= 0)` 제약이 된다.
- `ForeignKey` 필드 `question`은 컬럼 이름이 `question_id`가 되고 인덱스가 같이 만들어진다.

## 주피터에서 ORM 실행하기

ORM 코드는 원래 `python manage.py shell`에서 시험한다. 수업은 노트북에서 실행하려고 첫 셀에서 Django 환경을 직접 띄웠다. 노트북은 `manage.py`와 같은 폴더에 둔다.

```python
# ORM_Example.ipynb
# !uv pip install ipykernel

```

- `DJANGO_SETTINGS_MODULE`: 어느 `settings.py`를 쓸지 알려 준다. `manage.py`가 내부에서 하는 일이다.
- `DJANGO_ALLOW_ASYNC_UNSAFE`: 주피터는 비동기 이벤트 루프 위에서 돌아서, Django가 "비동기 환경에서 동기 DB 호출"이라며 막는 것을 풀어 준다. 개발용 설정이다.

```python
from polls.models import Question, Choice

# ModelClass.objects : (Model)Manager객체 -> select 처리 메소드들을 제공.
type(Question.objects)
```

```text
django.db.models.manager.Manager
```

모든 DB 작업은 `모델.objects`(Model Manager)에서 시작한다.

### 테스트 데이터 넣기

내 노트북에는 수업 예제 데이터를 다시 만드는 셀을 추가해 두었다. 기존 데이터를 지우고 SQLite의 자동 증가 번호까지 초기화한 뒤 질문 4개와 보기를 넣는다.

```python
from polls.models import Question, Choice
from django.db import connection

Choice.objects.all().delete()
Question.objects.all().delete()

# sqlite auto increment 리셋
with connection.cursor() as cursor:
    cursor.execute("DELETE FROM sqlite_sequence WHERE name='polls_choice'")
    cursor.execute("DELETE FROM sqlite_sequence WHERE name='polls_question'")

# Question 4개 INSERT
q1 = Question.objects.create(question_text="좋아하는 색은 무엇입니까?")
q2 = Question.objects.create(question_text="싫어하는 색은 무엇입니까?")
q3 = Question.objects.create(question_text="좋아하는 동물은 무엇입니까?")
q4 = Question.objects.create(question_text="여행가고 싶은 나라는 어디인가요?")

# Choice INSERT
Choice.objects.create(choice_text="파랑색", vote=12, question=q1)
Choice.objects.create(choice_text="검정색", vote=0, question=q1)
# ... (q1~q4의 보기 18개)
Choice.objects.create(choice_text="중국", vote=15, question=q4)
```

```text
<Choice: 18. 중국>
```

`sqlite_sequence`는 SQLite가 `AUTOINCREMENT` 번호를 기억하는 내부 테이블이다. 행을 지워도 번호는 이어지기 때문에 1번부터 다시 시작하려면 여기를 지운다(SQLite 전용이다).

그런데 이 노트북에는 보기 18개를 넣는 셀이 하나 더 있고(아래 `# 색 관련 (q1, q2 공유)` 셀), 그 셀도 실행됐다.

```text
<Choice: 36. 중국>
```

같은 질문 `q1~q4`에 보기가 한 번 더 들어가 **보기가 36개**가 됐다. 아래 결과에서 같은 보기가 두 번씩 나오는 것은 이 때문이다. 노트북에서 INSERT 셀은 실행할 때마다 데이터가 쌓이므로, 위처럼 "지우고 넣기"를 한 셀로 묶어 두고 그 셀만 실행하는 편이 안전하다.

## 조회

수업 노트의 정리다.

```text
# 조회
- Model Manager의 메소드들을 이용해서 조회
- `all()`: 전체 조회
- (where 절)조건으로 조회
    - `filter()`: 조건이 true 행들을 조회
    - `exclude()`: 조건이 false 행들을 조회
    - `get()`: 조건이 true 한개 행을 조회.(조회결과가 하나일때 사용.)
- all, filter, exclude, get 반환타입: `QuerySet`
- get 반환: 모델 객체
```

```python
# 모든 질문들을 조회
result = Question.objects.all()
print(type(result)) 
print("결과개수:", len(result))
print("첫번째 조회결과:", result[0], type(result[0]))
print(result.query) #sql문을 조회할 수 있음
```

```text
<class 'django.db.models.query.QuerySet'>
결과개수: 4
첫번째 조회결과: 1. 좋아하는 색은 무엇입니까? <class 'polls.models.Question'>
SELECT "polls_question"."id", "polls_question"."question_text", "polls_question"."pub_date" FROM "polls_question"
```

`QuerySet`은 for 문으로 돌 수 있고(iterable), 인덱싱·슬라이싱이 된다. 다만 음수 인덱스는 안 된다. 아래 셀은 에러가 나는 것이 정상이다.

```python
result[:2] # list
result[-1]  # 음수 indexing은 지원안함.
```

```text
[<Question: 1. 좋아하는 색은 무엇입니까?>, <Question: 2. 싫어하는 색은 무엇입니까?>]
ValueError: Negative indexing is not supported.
```

(에러는 강사님 노트북의 실행 결과) 마지막 행은 `result.last()`로 가져온다. SQL에는 "뒤에서 n번째"가 없어서, 음수 인덱스를 지원하려면 전체를 읽어야 하기 때문이다.

> **보충**: QuerySet은 **게으르다(lazy)**. `Question.objects.all()`을 만드는 순간에는 DB에 가지 않고, `len()`, `for`, 인덱싱처럼 실제 데이터가 필요할 때 SQL을 실행한다. 그래서 `.filter().order_by()...`처럼 이어 붙여도 SQL은 마지막에 한 번만 나간다.

### get: 정확히 한 건

`get()`은 결과가 **정확히 1건**일 때 쓰고 모델 객체를 바로 돌려준다. 0건이나 2건 이상이면 예외다.

```python
# Choice.objects.get(vote=0)   # 조회결과가 여러개인 경우는 에러발생.
try:
    Choice.objects.get(vote=300000)# 조회결과가 없는 경우 에러발생
except:
    print("조회결과가 없습니다.")
```

```text
조회결과가 없습니다.
```

주석 처리한 쪽까지 직접 실행해 예외 이름을 확인했다.

```text
Choice.objects.get(vote=300000) → DoesNotExist: Choice matching query does not exist.
Choice.objects.get(vote=0)      → MultipleObjectsReturned: get() returned more than one Choice -- it returned 2!
```

`except:`로 모든 예외를 잡으면 오타로 생긴 `AttributeError`까지 "조회결과가 없습니다"로 덮인다. `except Choice.DoesNotExist:`처럼 잡을 예외를 지정한다.

### filter와 Field lookup

`필드명__조건=값`(밑줄 두 개)으로 WHERE 조건을 만든다.

```python
# Where 조건
# Field명__연산자 = 비교할값
result = Choice.objects.filter(vote=0) # where vote = 0
result = Choice.objects.filter(vote__lt=50) # where vote < 50
result = Choice.objects.filter(vote__lte=33) # vote <= 33
result = Choice.objects.filter(vote__gt=60)   # vote > 60
result = Choice.objects.filter(vote__gte=60)   # vote >= 60

# 문자열
result = Choice.objects.filter(choice_text="빨강색")   
result = Choice.objects.filter(choice_text__startswith="파랑") # choice_text like '파랑%'
result = Choice.objects.filter(choice_text__endswith="색") # choice_text like '%색'
result = Choice.objects.filter(choice_text__contains="라") # choice_text like '%라%'

result = Choice.objects.filter(choice_text__in = ['보라색', '빨강색', "개"])
result = Choice.objects.filter(vote__range=[50, 100])# vote between 50 and 100

for choice in result:
    print(choice.choice_text, choice.vote)

print(result.query) #QuerySet.query : 실행된 SQL문
```

```text
사자 60
사자 60
SELECT "polls_choice"."id", "polls_choice"."choice_text", "polls_choice"."vote", "polls_choice"."question_id" FROM "polls_choice" WHERE "polls_choice"."vote" BETWEEN 50 AND 100
```

`result`를 계속 덮어써서 마지막 `range` 결과만 출력됐다. "사자"가 두 번인 것은 앞에서 본 보기 중복 때문이다.

| lookup | SQL |
|---|---|
| `필드=값` | `= 값` (값이 None이면 `IS NULL`) |
| `__lt`, `__lte`, `__gt`, `__gte` | `<`, `<=`, `>`, `>=` |
| `__startswith`, `__endswith`, `__contains` | `LIKE '값%'`, `'%값'`, `'%값%'` |
| `__in=[...]` | `IN (...)` |
| `__range=[a, b]` | `BETWEEN a AND b` |

### AND와 OR

인자를 나열하면 AND다.

```python
# 조건이 여러개인 경우 - AND, OR
# AND - 조건을 나열.
result = Choice.objects.filter(
    vote__lt = 100,
    choice_text__in = ['파랑색', '검정색', '개', '고양이']
)

print(result.query)
```

```text
SELECT "polls_choice"."id", "polls_choice"."choice_text", "polls_choice"."vote", "polls_choice"."question_id" FROM "polls_choice" WHERE ("polls_choice"."choice_text" IN (파랑색, 검정색, 개, 고양이) AND "polls_choice"."vote" < 100)
```

OR와 NOT은 `Q` 객체를 `|`, `~`로 묶는다.

```python
# OR - Q 클래스에 조건을 넣어 주고 `|`  연산으로 묶어준다.
## Q(조건) | Q(조건) | Q(조건)
from django.db.models import Q 
# vote 가 10 이하거나 100 이상

# ~Q(조건)  not 조건
result = Choice.objects.filter(
    Q(vote__lte=10) | Q(vote__gte=100)
)
print(result.query)
```

```text
SELECT "polls_choice"."id", "polls_choice"."choice_text", "polls_choice"."vote", "polls_choice"."question_id" FROM "polls_choice" WHERE ("polls_choice"."vote" <= 10 OR "polls_choice"."vote" >= 100)
```

> **보충**: `.query`가 보여 주는 SQL에서 `IN (파랑색, 검정색, ...)`에 따옴표가 없다. `.query`는 사람이 읽기 위한 문자열일 뿐이고, 실제 실행 때는 값을 **파라미터로 따로 넘긴다**. 그래서 ORM을 쓰면 SQL 인젝션이 막힌다. 출력된 SQL을 복사해 DB 도구에 붙이면 문법 오류가 나는 이유도 이것이다.

## 집계

```text
# 집계
- 'aggregate(집계함수("field명), 집계함수("field명).....)'

```

(노트의 `wlqrPgkatn`은 한/영 전환을 못 하고 친 "집계함수"다.)

집계 함수는 `django.db.models`에 있다. import 셀에 각 이름이 어디서 오는지 적어 두었다.

```python
from polls.models import Question, Choice
from django.db import models

# # import => 
# polls — 내가 만든 앱 폴더

# django — Django 프레임워크 패키지
# db — 데이터베이스 관련 모듈
# models — ORM 기능 모음 (CharField, ForeignKey, Model 등)
```

```python
result = Choice.objects.aggregate(
    cnt = models.Count("id"), # keyword argument로 전달 변수명이 key가 된다.
    avg = models.Avg("vote"),
)
print(result)
```

```text

```

키워드 인자 없이 쓰면 `id__count`, `vote__avg`처럼 `필드__함수` 이름이 자동으로 붙는다. 반환은 QuerySet이 아니라 **딕셔너리**다.

```python
result = Choice.objects.aggregate(
```

| `... GROUP BY question_id` | `values("question").annotate(...)` |

`choice_set`이 다음 글의 설문 폼에서 질문의 보기 목록을 꺼내는 방법이다.

|---|---|---|

### 날짜 출력에서 생긴 실수

```python
q1 = Question.objects.get(pk=1)
q1.pk, q1.question_text, q1.pub_date.strftime("%Y-%M-%d")
```

```text
(1, '좋아하는 색은 무엇입니까?', '2026-17-27')
```

17월이 나왔다. `strftime`에서 **`%M`은 분(minute)**, 월은 소문자 `%m`이다. 등록 시각이 01시 17분이라 17이 들어갔다.

```python
q1.pub_date.strftime("%Y-%m-%d")
```

또 하나, `pub_date`를 그대로 찍으면 시간대가 UTC다.

```text
datetime.datetime(2026, 7, 27, 1, 17, 45, 921462, tzinfo=datetime.timezone.utc)
```

`settings.py`가 `USE_TZ = True`라 DB에는 UTC로 저장하고, 템플릿에서 출력할 때 `TIME_ZONE = 'Asia/Seoul'`로 바꿔 보여 준다. 파이썬 코드에서 한국 시간이 필요하면 `django.utils.timezone.localtime()`을 거친다. 직접 실행한 비교다.

```text
2026-42-08 | 2026-10-08 08:42 | 2026-10-08 17:42
```

순서대로 `%M` 실수, UTC 그대로, `localtime()` 적용 결과다.

## 등록·수정·삭제

```text
# Insert/Update
- 'model객체.save()'
    -모델객체를 한행으로 insert/update처리
    -instance변수들의 값이 연결된 테이블의 컬럼에 저장
- 모델 객체의 'pk'가 테이블에없으면 'insert', 없으면 'update'
```

(노트의 마지막 줄 "없으면 'update'"는 "있으면 update"의 오타다.)

```python
# insert
new_question = Question(question_text="좋아하는 운동은 무엇입니까?")
#pk, pib_date => None(insert할 때 자동으로 등록)
new_question.save()
```

```python
update_question = Question.objects.get(pk=6)
print(update_question)
print(update_question.pub_date)

update_question.question_text = "무슨 운동하시부리까?"
update_question.save()

r = Question.objects.get(pk=6)
print(r)
print(r.pub_date)
```

```text
2026-07-27 02:34:23.638003+00:00
```

수정 후에도 `pub_date`가 그대로다. `auto_now_add`는 **처음 INSERT 때만** 값을 넣는다. 수정 시각을 남기려면 `auto_now=True` 필드를 따로 둔다.

삭제는 `delete()`다. 조회하지 않고 PK만 가진 객체를 만들어 지워도 된다.

```python

```

```text
(1, {'polls.Question': 1})
```

반환값은 (지운 행 수, 모델별 개수)다. 질문을 지우면 `on_delete=CASCADE`로 그 질문의 보기도 같이 지워지고 개수에 함께 잡힌다(이 질문은 보기가 없었다).

마지막 두 셀은 오타로 에러가 났다. 아래 셀은 에러가 나는 것이 정상이다.

```python
qs = Question.objects.a
ll()
```

```text
AttributeError: 'Manager' object has no attribute 'a'
```

```python
del_qs = Question.object.filter(pk__in = [2,4])
```

```text
AttributeError: type object 'Question' has no attribute 'object'
```

`all()` 가운데서 줄이 바뀌어 `objects.a`가 됐고, 다음 셀은 `objects`의 `s`가 빠졌다. 여러 행을 한 번에 지우려던 의도는 이렇게 쓴다.

```python
Question.objects.filter(pk__in=[2, 4]).delete()
```

> **보충**: `Model.save()`로 하나씩 고치는 대신 QuerySet 단위로도 처리한다. `Choice.objects.filter(question=q1).update(vote=0)`은 UPDATE 한 번, `.delete()`는 DELETE 한 번이다. 대신 모델의 `save()`를 거치지 않으므로 `auto_now` 같은 동작은 적용되지 않는다.

## 정리

| 하고 싶은 것 | ORM | SQL |
|---|---|---|
| 전체 | `Model.objects.all()` | `SELECT *` |
| 조건 | `filter(vote__gte=60)` | `WHERE vote >= 60` |
| 제외 | `exclude(vote=0)` | `WHERE NOT vote = 0` |
| 한 건 | `get(pk=1)` | 0건·2건 이상은 예외 |
| OR / NOT | `Q(a) \| Q(b)`, `~Q(a)` | `OR`, `NOT` |
| 정렬 | `order_by("-vote", "choice_text")` | `ORDER BY vote DESC, ...` |
| 컬럼 지정 | `values("pk", "choice_text")` | `SELECT id, choice_text` |
| 집계 | `aggregate(Sum("vote"))` | `SELECT SUM(vote)` |
| 그룹 집계 | `values("question").annotate(Max("vote"))` | `GROUP BY` |
| 부모 / 자식 | `choice.question` / `question.choice_set` | JOIN |
| 등록·수정 | `obj.save()` | INSERT / UPDATE |
| 삭제 | `obj.delete()` | DELETE |

- Model을 고치면 `makemigrations` → `migrate`.
- `.query`로 실행될 SQL을 확인하는 습관을 들인다.
- 노트북의 INSERT 셀은 실행 횟수만큼 데이터가 쌓인다.
