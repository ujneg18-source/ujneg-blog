## 클라우드란

클라우드는 서버·스토리지·네트워크 같은 컴퓨팅 자원을 인터넷으로 **필요할 때 필요한 만큼 빌려 쓰고, 쓴 만큼 내는** 환경이다.

| 방식 | 의미 |
|---|---|
| 온디맨드(On-Demand) | 요청하면 즉시 자원을 제공하고 사용량만큼 과금 |
| 온프레미스(On-Premises) | 기업이 물리 서버를 직접 사서 자기 시설에서 운영 |

온프레미스는 서버를 사는 초기 비용과 설치 시간이 들고, 사용자가 갑자기 늘면 서버를 새로 사야 한다. 클라우드는 몇 분 만에 서버를 만들고 필요 없으면 지운다.

| 장점 | 내용 |
|---|---|
| 비용 | 초기 구축비 없음, 유지보수 부담 감소 |
| 운영 | 자원을 빠르게 늘리고 줄임, 어디서나 접근 |
| 기술 | 높은 가용성, 자동 백업·재해 복구, 최신 기술 사용 |

대표 서비스는 AWS, Microsoft Azure, Google Cloud Platform(GCP), Oracle Cloud(OCI)다.

## IaaS · PaaS · SaaS

"어디까지 빌려 주느냐"에 따라 나눈다.

| 유형 | 제공하는 것 | 사용자가 관리하는 것 | 예 |
|---|---|---|---|
| IaaS | 가상화된 서버·스토리지·네트워크 | OS 설치·업데이트, 런타임, 앱 | AWS EC2, Azure VM, Google Compute Engine |
| PaaS | IaaS + OS·런타임·DB 등 개발 환경과 그 유지관리 | 앱 코드 | AWS Elastic Beanstalk, Google App Engine, Azure App Service |
| SaaS | 완성된 소프트웨어 | 사용만 | Gmail·Google Drive, Microsoft 365, Dropbox |

노트북에 이렇게 메모해 두었다.

```python
# platform as a service(PaaS) : 플랫폼을 제공하는 서비스로 개발자가 애플리케이션을 개발하고 배포할 수 있는 환경을 제공하는 서비스입니다.
# EC2 : Elastic Compute Cloud의 약자로, AWS에서 제공하는 가상 서버 인스턴스를 의미합니다. 
```

```python
# DB - Paas
# H/W - Iaas
```

두 번째 메모가 이 시리즈의 구조다. 서버(EC2)는 **IaaS**라서 Ubuntu 업데이트, 파이썬 설치, 웹 서버 설정을 직접 한다(2~4편). DB(RDS)는 설치·백업·패치를 AWS가 맡는 관리형 서비스라 PaaS에 가깝다(3편).

> **보충**: "피자"로 자주 비유한다. 온프레미스는 집에서 직접 만들기, IaaS는 재료를 사 와서 집에서 굽기, PaaS는 배달, SaaS는 식당에서 먹기다. 아래로 갈수록 편하지만 마음대로 바꿀 수 있는 범위가 줄어든다.

## 가입

aws.amazon.com에서 **AWS 계정 생성** → 이메일 인증 → 비밀번호 → **플랜 선택** → 연락처(개인, 국가 대한민국, 시·도는 영문) → 신용카드 등록과 인증 → 휴대폰 SMS 인증 순서다.

수업 자료에 정리된 플랜 차이다.

| | 무료 플랜(Free Plan) | 유료 플랜(Paid Plan) |
|---|---|---|
| 목적 | 초보자의 의도치 않은 과금 방지 | 일반 종량제(Pay-as-you-go) |
| 크레딧 | \$100 + 학습 미션으로 최대 \$100 추가 | 같은 크레딧 제공 |
| 제한 | 과금될 수 있는 서비스·기능은 생성 자체를 막음 | 제한 없음 |
| 기간 | 최대 6개월, 크레딧 소진 또는 기간 만료 시 계정 만료 | 크레딧 소진 후 사용량만큼 청구 |

AWS를 처음 쓰면 무료 플랜을 고른다. 무료 플랜이 끝나면 유료 플랜으로 전환한다.

> **보충**: 무료 플랜과 별개로 **프리티어**는 "정해진 사양·사용량 안에서는 무료"인 서비스 목록이다(2편에서 EC2 사양을 고를 때 나온다). 수업은 Django와 VSCode 원격 접속을 위해 프리티어보다 큰 `t3.medium`을 썼으므로 크레딧이 차감된다.

## MFA(멀티팩터 인증)

가입한 계정은 **루트 사용자**로, 결제와 계정 삭제까지 모든 권한을 가진다. 비밀번호 하나로 지키기에는 위험하다. MFA는 비밀번호(1차)에 스마트폰 인증 앱의 일회용 코드(OTP, 2차)를 더한다.

1. 오른쪽 위 계정 메뉴 → **보안 자격 증명**
2. 멀티 팩터 인증(MFA) → **MFA 디바이스 할당** → **인증 앱**
3. 스마트폰에 인증 앱 설치(Google Authenticator 등) → **QR 코드 표시** → 앱에서 스캔
4. 앱에 뜨는 코드를 **첫 번째 코드**에 넣고, 30초쯤 뒤 바뀐 코드를 **두 번째 코드**에 넣는다

이후 로그인은 **루트 사용자** 선택 → 이메일 → 비밀번호 → 인증 앱 코드 순서다.

> **보충**: 강의는 루트 계정으로 바로 실습했다. 실무에서는 루트 계정은 MFA를 걸어 잠가 두고, **IAM 사용자**를 만들어 필요한 권한만 주고 평소에는 그 계정을 쓴다. 팀 프로젝트에서 계정을 공유해야 할 때도 루트 비밀번호 대신 IAM 사용자를 사람마다 만든다.

## 리전

AWS는 전 세계 여러 지역(리전)에 데이터 센터가 있고, **서비스는 리전별로 만들어진다.** 서울 리전에서 만든 서버는 다른 리전을 선택한 화면에서는 보이지 않는다. 처음 로그인하면 오른쪽 위에서 **아시아 태평양(서울)**으로 바꾼다.

"만든 서버가 사라졌다"는 일의 대부분은 리전이 바뀐 것이다. 사용자와 가까운 리전을 고르면 응답도 빠르다.

## 비용 확인

**계정 메뉴 → 결제 및 비용 관리**에서 사용 금액을 본다. 가입 후 하루 정도 지나야 데이터가 나오고, 루트 계정이나 결제 권한이 있는 IAM 계정만 볼 수 있다.

> **보충**: 쓴 만큼 내는 구조라 "켜 두고 잊은 서버"가 가장 흔한 과금 원인이다. 결제 및 비용 관리의 **Budgets(예산)** 에서 월 예산(예: \$10)을 정하고 초과 시 이메일 알림을 받도록 해 두면 늦게 알아차리는 일을 막을 수 있다. 2편에서 볼 **중지해도 과금되는 것**(디스크, 탄력적 IP)도 함께 기억해 둔다.
