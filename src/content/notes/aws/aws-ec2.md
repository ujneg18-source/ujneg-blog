## VPC와 서브넷

VPC(Virtual Private Cloud)는 AWS 안에 논리적으로 만드는 **나만의 가상 네트워크**다. EC2 인스턴스는 반드시 어떤 VPC 안에 만들어진다.

수업 자료의 네트워크 설명이다.

> 네트워크는 서로 직접 통신할 수 있는 컴퓨터들의 논리적 집합이다. IP 주소는 **네트워크 주소**와 **호스트 주소**로 구성된다. 네트워크 주소가 같으면 같은 네트워크에 속해 라우터 없이 직접 통신하고, 호스트 주소는 그 안에서 각 컴퓨터를 구분한다. **서브넷**은 큰 네트워크를 여러 개의 작은 네트워크로 나눈 것이다.

둘을 어디서 나누는지를 **CIDR**로 표기한다.

```text
192.168.1.10/24
└──────┘ └┘
 앞 24비트(192.168.1) = 네트워크 주소
 나머지 8비트(10)     = 호스트 주소  → 이 네트워크에는 192.168.1.0 ~ 255
```

`/16`이면 앞 16비트가 네트워크라서 훨씬 큰 네트워크(약 6만 5천 개 주소)다. VPC를 `/16`으로 만들고, 그 안을 `/24` 서브넷 여러 개로 나누는 식이다.

서브넷은 두 종류가 있다.

| | 퍼블릭 서브넷 | 프라이빗 서브넷 |
|---|---|---|
| 인터넷 연결 | 인터넷 게이트웨이로 직접 연결 | 외부에서 직접 들어올 수 없음 |
| 두는 것 | 웹 서버 | DB 서버 |

**VPC 콘솔 → VPC 생성 → "VPC 등"** 을 선택하고 기본값으로 만들면 서브넷(퍼블릭·프라이빗), 라우팅 테이블, 인터넷 게이트웨이까지 한 번에 만들어 준다. "VPC만"을 고르면 이것들을 하나씩 직접 만들어야 한다.

## EC2 인스턴스 만들기

**EC2 콘솔 → 인스턴스 시작**. 먼저 오른쪽 위 리전이 **서울**인지 확인한다.

### 이름과 AMI

- **이름**: 서버 역할이 드러나게 짓는다(`dev-web-server`, `prod-web-server`).
- **AMI(Amazon Machine Image)**: OS와 기본 소프트웨어가 담긴 템플릿. 수업은 **Ubuntu**를 골랐다.

### 인스턴스 유형

CPU·메모리 등 하드웨어 사양이다. 프리티어 표시가 있는 유형(`t2.micro`, `t3.micro` 등)은 정해진 사용량 안에서 무료지만, 메모리가 1GB 수준이라 VSCode 원격 접속이나 Django + LangChain 실행에는 부족하다. 수업은 **`t3.medium` 이상**을 쓰라고 안내했다.

### 키 페어

SSH 접속에 쓰는 인증 키 한 쌍이다.

| 키 | 보관 | 역할 |
|---|---|---|
| 퍼블릭 키 | 서버(EC2)에 등록됨 | 서명 검증 |
| 프라이빗 키(`.pem`) | 내 PC | 접속할 때 서명 |

접속할 때 내 PC가 프라이빗 키로 서명하고, 서버가 퍼블릭 키로 그 서명을 확인해 비밀번호 없이 인증한다.

**새 키 페어 생성** → 이름(어느 인스턴스용인지 드러나게) → 형식 **`.pem`** → 생성하면 파일이 내려받아진다.

> **보충**: 수업 자료에는 이때 "public key 파일이 다운로드된다"고 적혀 있는데, 내려받는 `.pem`은 **프라이빗 키**다. 퍼블릭 키는 AWS가 인스턴스에 넣어 둔다. 프라이빗 키는 **이때 한 번만** 받을 수 있고, 이 파일을 가진 사람은 누구나 서버에 접속할 수 있다. Git 저장소나 메신저에 올리지 않는다(`.gitignore`에 `*.pem` 추가).

### 네트워크 설정

**편집**을 눌러 직접 고른다.

- **VPC**: 위에서 만든 VPC
- **서브넷**: 이름에 `public`이 들어간 것. 기본값은 아무 서브넷이나 고를 수 있는데, 프라이빗 서브넷에 만들면 외부에서 접속할 수 없다.
- **퍼블릭 IP 자동 할당**: **활성화**
- **보안 그룹**: 새로 만들고 이름·설명을 구분되게 적는다.

**보안 그룹**은 인스턴스 앞의 방화벽이다. 어떤 **IP 범위**에서 어떤 **포트**로 들어오는 것을 허용할지(인바운드), 나가는 것을 허용할지(아웃바운드)를 규칙으로 정한다. 기본은 SSH(22번)만 열려 있다.

### 스토리지

인스턴스에 붙는 디스크(EBS)다. `gp3`(최신), 30GB까지 프리티어 범위다.

## 인스턴스 상태와 과금

| 동작 | 의미 | 과금 |
|---|---|---|
| 중지 | 컴퓨터 끄기 | 인스턴스 요금 멈춤. **스토리지(EBS)는 계속 과금** |
| 시작 | 다시 켜기 | 다시 과금 |
| 종료 | **삭제** | 완전히 멈춤(디스크도 기본 설정상 함께 삭제) |

수업 기간 중에는 쓰지 않을 때 **중지**하고, 끝나면 **종료**한다. 중지만 해 두면 디스크 요금이 계속 나간다.

> **보충**: 중지했다가 다시 시작하면 **퍼블릭 IP가 바뀐다.** 아래 SSH 설정과 Django의 `ALLOWED_HOSTS`, NGINX의 `server_name`에 IP를 적어 두었다면 다 고쳐야 한다. 이것이 아래 탄력적 IP를 쓰는 이유다.

## 접속하기

### EC2 Instance Connect

인스턴스 선택 → **연결** → **연결**. 브라우저에 터미널이 열린다. 처음 접속하면 Ubuntu 패키지를 업데이트한다.

```bash
sudo apt update     # 패키지 목록을 새로 받아 새 버전이 있는지 확인
sudo apt upgrade    # 설치된 패키지를 최신 버전으로
```

### SSH

SSH(Secure Shell)는 내 PC 터미널에서 원격 서버의 셸에 **암호화된 연결**로 접속하는 프로토콜이다. TCP **22번 포트**를 쓰고, 평문으로 통신하던 Telnet을 대체했다.

```bash
ssh -i "프라이빗키.pem 경로" ubuntu@<EC2 퍼블릭 IP>
```

- Ubuntu AMI의 기본 계정은 `ubuntu`다.
- 처음 접속하면 "이 서버를 신뢰하느냐"고 묻는다. `yes`를 입력하면 서버 지문이 `~/.ssh/known_hosts`에 저장된다.
- Mac·Linux는 키 파일 권한을 본인 읽기 전용으로 바꿔야 한다. 권한이 넓으면 SSH가 키 사용을 거부한다.

```bash
chmod 400 프라이빗키.pem
```

- Windows는 사용자 홈의 `.ssh` 폴더로 옮겨 둔다.

### ssh config

매번 IP와 키 경로를 치지 않도록 `~/.ssh/config`에 접속 정보를 저장한다.

```text
Host my-server
    HostName <EC2 퍼블릭 IP>
    User ubuntu
    IdentityFile ~/.ssh/my-server-key.pem
```

이후에는 `ssh my-server`로 접속한다. 포트를 생략하면 22번이다. 다음 글의 VSCode 원격 접속도 이 파일을 쓴다.

## 인바운드 규칙: 포트 열기

서버에서 Jupyter, Streamlit, Django 개발 서버를 띄워도 보안 그룹이 막고 있으면 외부에서 접속할 수 없다.

**EC2 → 네트워크 및 보안 → 보안 그룹** → 인스턴스의 보안 그룹 선택 → **인바운드 규칙 편집** → **규칙 추가**

| 항목 | 값 |
|---|---|
| 유형 | 사용자 지정 TCP |
| 포트 범위 | Jupyter 8888, Streamlit 8501, Django 개발 서버 8000, HTTP 80 |
| 소스 | Anywhere-IPv4(`0.0.0.0/0`) |

> **보충**: `0.0.0.0/0`은 "모든 IP"다. 웹 서비스 포트(80, 443)는 누구나 들어와야 하니 맞지만, **SSH(22)나 Jupyter(8888)를 모두에게 열면** 전 세계 자동 스캐너의 공격 대상이 된다. 이런 관리용 포트는 소스를 **내 IP**로 지정한다. 4편의 배포 구성에서는 NGINX가 80번으로 받으므로 8000번은 테스트 후 닫는다.

## 탄력적 IP

인스턴스를 중지했다 켜면 퍼블릭 IP가 바뀐다. **탄력적 IP**는 계정에 고정 IP를 할당받아 인스턴스에 붙이는 것이다.

1. **EC2 → 네트워크 및 보안 → 탄력적 IP → 탄력적 IP 주소 할당** → 기본값으로 **할당**
2. 할당된 주소 선택 → **작업 → 탄력적 IP 주소 연결** → 인스턴스 선택

삭제는 순서가 있다. **연결 해제**를 먼저 하고 **릴리스**(반납)한다.

> **보충**: AWS는 2024년부터 퍼블릭 IPv4 주소에 **연결 여부와 관계없이** 시간당 요금을 받는다. 탄력적 IP도 마찬가지라, 실습이 끝나면 인스턴스 종료와 함께 탄력적 IP도 릴리스해야 요금이 멈춘다. 요금은 바뀔 수 있으니 공식 요금표를 확인한다.

## 정리

| 항목 | 기억할 것 |
|---|---|
| VPC | 나만의 가상 네트워크. "VPC 등"으로 서브넷·게이트웨이까지 생성 |
| 서브넷 | 웹 서버는 **public** 서브넷 |
| CIDR | `/24` = 앞 24비트가 네트워크 |
| 인스턴스 유형 | 실습은 `t3.medium` 이상 |
| 키 페어 | 내려받는 `.pem`은 **프라이빗 키**, 한 번만 받음 |
| 보안 그룹 | 인바운드 규칙으로 포트 열기, 관리 포트는 내 IP만 |
| 중지 / 종료 | 중지해도 디스크 과금, 종료는 삭제 |
| 탄력적 IP | 고정 IP. 해제 → 릴리스 |
| 접속 | `ssh -i 키 ubuntu@IP`, `~/.ssh/config` |
