## 이 글에서 다루는 것

- 정규 표현식의 구성: 패턴, 메타 문자, 리터럴
- 메타 문자: 문자 클래스 `[ ]`, 미리 정의된 클래스(`\d`, `\w`, `\s`, `\b`), 수량자, `^` `$`, `.` `|` `( )`
- 파이썬 `re` 모듈: `match`, `search`, `findall`, `finditer`, `sub`, `subn`
- 그룹핑: 하위 그룹 조회, 패턴 안 역참조 `\1`, 치환 문자열 참조 `\g<1>`

- 전방 탐색과 후방 탐색

지난 글의 전처리 단계 중 노이즈 제거와 정규화는 대부분 정규 표현식으로 한다. URL 지우기, 공백 줄이기, 전화번호나 주민번호 찾기가 모두 "패턴"으로 표현된다.

## 정규 표현식이란

- 특정한 **패턴**을 가진 문자열을 **검색, 추출, 수정**하는 기법이다
- 파이썬뿐 아니라 문자열을 다루는 거의 모든 곳(편집기, DB, 다른 언어)에서 쓴다

**주요 용도**

- **문자열 검색**: 패턴에 맞는 문자열을 찾는다
- **문자열 변경**: 패턴에 맞는 부분을 다른 문자열로 바꾸거나 지운다
- **유효성 검사**: 이메일 주소, 전화번호 같은 형식이 맞는지 확인한다

**구성 요소**

- **패턴**: 찾으려는 문자열의 규칙을 정의한 표현식. 메타 문자와 리터럴로 이뤄진다
- **메타 문자**: 패턴에서 특별한 규칙을 나타내는 문자. 예) `a*`: a가 0회 이상 반복 → `a`, `aa`, `aaaa`
- **리터럴**: 문자 그 자체. 예) `a`는 `a`를 뜻한다

## 메타 문자

### 문자 클래스 `[ ]`

`[ ]` 안의 문자 중 **한 글자**와 매칭된다.

| 패턴 | 의미 |
|---|---|
| `[abc]` | a, b, c 중 한 글자 |
| `[a-z]` | 알파벳 소문자 중 한 글자 (`-`로 범위 지정) |
| `[a-zA-Z0-9]` | 알파벳 대소문자와 숫자 중 한 글자 |
| `[가-힣ㄱ-ㅎㅏ-ㅣ]` | 한글 중 한 글자 |
| `[^abc]` | `^`로 시작하면 반대. a, b, c를 **제외한** 한 글자 |
| `[^a-z]` | 소문자를 제외한 한 글자 |

### 미리 정의된 문자 클래스

| 패턴 | 의미 | 같은 표현 |
|---|---|---|
| `\d` | 숫자 | `[0-9]` |
| `\D` | 숫자가 아닌 문자 | `[^0-9]` |
| `\w` | 문자, 숫자, `_` (특수문자를 뺀 일반 문자, 언어 무관) | `[a-zA-Z가-힣0-9_]` |
| `\W` | `\w`의 반대 | `[^a-zA-Z가-힣0-9_]` |
| `\s` | 공백 문자 (공백, tab, 줄바꿈) | |
| `\S` | 공백이 아닌 문자 | |
| `\b` | 단어 경계 (공백, `,`, `.`, `\n` 등) | |
| `\B` | 단어 경계가 아닌 곳 | |

- `\b`는 문자와 매칭되는 게 아니라 **경계만 확인**한다. 단어의 시작과 끝을 찾을 때 쓴다
  - `\bcat\b`는 "The **cat** is"의 cat에만 매칭되고, "**cat**egory"나 "con**cat**enate"에는 매칭되지 않는다
- `\B가족\B` → "우리 가족 만세"(X), "우리가족만세"(O)

### 수량자 (quantifier)

앞의 문자(패턴)가 몇 번 나오는지 정한다.

| 패턴 | 의미 | 예 |
|---|---|---|
| `*` | 0개 이상 | `a*b` |
| `+` | 1개 이상 | `a+b` |
| `?` | 0개 또는 1개 | `a?b` |
| `{m}` | 정확히 m개 | `a{3}b` |
| `{m,}` | m개 이상 (`,` 뒤에 공백을 넣지 않는다) | `a{3,}b` |
| `{m,n}` | m개 이상 n개 이하 | `a{2,5}b` |

### 문장의 시작과 끝, 기타

| 패턴 | 의미 |
|---|---|
| `^` | 문자열의 시작 (`^abc`). 문자 클래스 안의 `^`(부정)와는 의미가 다르다 |
| `$` | 문자열의 끝 (`abc$`) |
| `.` | 줄바꿈(`\n`)을 제외한 아무 문자 한 개 (`a.b`) |
| `\|` | 둘 중 하나(OR). `(?:010\|011\|016\|019)` |
| `( )` | 패턴 안에 하위 그룹을 만든다 |

`|`는 우선순위가 가장 낮아서 `010|016-111`은 "010" 또는 "016-111"이 된다. 일부만 OR로 묶으려면 괄호가 필요하다.

> 패턴을 테스트해 볼 수 있는 사이트: [regexr.com](https://regexr.com/)

## 파이썬에서 정규 표현식 쓰기: `re` 모듈

- 표준 라이브러리 `re`를 쓴다. 다른 여러 패키지도 내부적으로 정규 표현식을 쓴다
- 두 가지 코딩 방식이 있다

| 방식 | 코드 |
|---|---|
| 객체지향형: 패턴 객체를 만들고 메소드 호출 | `p = re.compile(r'\d+')` → `p.search('abc123def')` |
| 함수형: `re` 모듈 함수에 패턴과 대상 전달 | `re.search(r'\d+', 'abc123def')` |

같은 패턴을 여러 번 쓸 때는 `compile`해 두는 객체지향형이 편하다.

> **raw string**
> 파이썬은 문자열 안의 `\`를 escape 문자로 먼저 처리한다. 그런데 미리 정의된 문자 클래스는 모두 `\`로 시작해서, 일반 문자열로 쓰면 `\\`처럼 두 번씩 써야 한다. 그래서 패턴은 **raw string**(`r"..."`)으로 쓴다.
> - `re.compile('\b가족\b')`: `\b`를 escape 문자(백스페이스)로 인식한다
> - `re.compile(r'\b가족\b')`: `\b`가 그대로 정규식 메타 문자로 전달된다

## 검색 함수

| 함수 | 용도 | 반환 |
|---|---|---|
| `match(대상, pos=0)` | 대상의 **시작**이 패턴과 일치하는지 | Match 객체 / None |
| `search(대상, pos=0)` | 대상 **전체 안에** 패턴과 일치하는 것이 있는지 | Match 객체 / None (첫 번째 것만) |
| `findall(대상)` | 일치하는 문자열을 **모두** 찾는다 | 문자열 리스트 (없으면 빈 리스트) |
| `finditer(대상)` | 일치하는 결과를 하나씩 꺼내는 iterator | Match 객체들의 iterator |

`pos`는 찾기 시작할 index다.

**Match 클래스**: 검색 결과 **하나**를 담는다. `match()`, `search()`의 반환 타입이다.

| 메소드 | 반환 |
|---|---|
| `group()` | 찾은 문자열 |
| `group(번호)` | 패턴에 하위 그룹이 있을 때, 그 그룹의 문자열 |
| `start()`, `end()` | 대상 문자열 안에서의 시작, 끝 index |
| `span()` | (시작, 끝) 튜플 |

```python
txt1 = "안녕하세요. 반갑습니다. 오늘 날씨는 3도입니다. 좋은 하루 되세요."
txt2 = "반갑습니다. 안녕하세요. 오늘 날씨는 3도입니다. 좋은 하루 되세요. 반갑습니다."
txt3 = "가격은 각각 1000, 2000, 3000, 60000원 입니다."
```

```python
import re
```

```python
# match() - 객체지향방식
p = re.compile(r"[가-힣]+습니다\.") # [가-힣] 모든 한글문자 1글자.
                           # + 수량사로 앞의 패턴이 한글자 이상
                           # 습니다 -> literal(리터럴)
                           # `\.`  .: 모든 한글자. 마침표: \. 
                           # ~~~~~습니다.
# result = p.match(txt1) # txt1이 p의 패턴으로 **시작하는지** 여부.
# result = p.match(txt2)
# result = p.match(txt2, pos=7) # index 7 에서부터 찾는다.

# result = p.search(txt1)  # txt1안에 패턴의 문자열이 있는지 검색.
# result = p.search(txt2)
result = p.search(txt2, pos=5) # index 5에서부터 찾는다.

if result != None:
    print(result)
    print(result.group()) # 찾은 문자열을 반환.
    print(result.start(), result.end()) # 찾은 문자열의 시작/끝-1 위치
    print(result.span())
else: # None
    print(result, "패턴이 일치하지 않습니다.")
```

```text
<re.Match object; span=(39, 45), match='반갑습니다.'>
반갑습니다.
39 45
(39, 45)
```

`pos=5`부터 찾으니 맨 앞의 "반갑습니다."는 건너뛰고, 끝의 "반갑습니다."를 찾았다. 주석에 있는 다른 줄들의 결과를 한 번에 비교해 본다.

```python
# 보충: 주석 처리된 경우들의 결과
cases = {
    "p.match(txt1)": p.match(txt1),
    "p.match(txt2)": p.match(txt2),
    "p.match(txt2, pos=7)": p.match(txt2, pos=7),
    "p.search(txt1)": p.search(txt1),
    "p.search(txt2)": p.search(txt2),
}
for k, v in cases.items():
    print(f"{k:22} → {v.group() if v else None}")
```

```text
p.match(txt1)          → None
p.match(txt2)          → 반갑습니다.
p.match(txt2, pos=7)   → None
p.search(txt1)         → 반갑습니다.
p.search(txt2)         → 반갑습니다.
```

- `match(txt1)`: txt1은 "안녕하세요."로 시작해서 None. 하지만 `search(txt1)`은 안쪽의 "반갑습니다."를 찾는다
- `match(txt2, pos=7)`: index 7은 "안녕하세요."의 시작이라 None

> **보충** 주석의 "찾은 문자열의 시작/끝-1 위치"에서 `end()`는 마지막 글자의 **다음** index다. 그래서 `txt2[39:45]`처럼 슬라이싱에 그대로 쓸 수 있다.

```python
txt3 = "가격은 각각 800000, 1000, 2000, 3000, 60000 원 입니다."

# 함수형 방식
import re
# txt3에서 만단위 숫자가 있는지 확인
result = re.search(r"\b\d{5}\b", txt3) # , pos=3) [0-9] -> \d, {5} 5개
print(result)

# 객체지향방식
p = re.compile(r"\b\d{5}\b")
print(p.search(txt3))
print(p.match(txt3))
```

```text
<re.Match object; span=(33, 38), match='60000'>
<re.Match object; span=(33, 38), match='60000'>
None
```

`\b`로 양쪽 경계를 막아서 800000의 일부(80000)는 걸리지 않고 60000만 찾았다. `match`는 문자열이 "가격은"으로 시작하니 None이다.

# txt3에서 숫자들을 모두 조회

result
```

### 예제: 주민번호와 이메일 추출

`info` 변수는 한 줄에 한 사람의 데이터가 **`이름 이메일주소 주민번호`** 순서로 들어 있다. (모두 가짜 데이터다)

info ='''김정수 kjs@gmail.com 801023-1010221
박영수 pys.abc@gmail.com 700121-1120212
이민영 lmy-abc@naver.com 820301-2020122

```

# 주민번호들만 조회해서 출력
# 숫자6-숫자7
p = re.compile(r"\d{6}-[1-8]\d{6}")

result2 = p.finditer(info)
list(result2)
```

```

뒷자리 첫 숫자를 `[1-8]`로 제한해서 성별 자리에 올 수 없는 숫자(0, 9)는 걸러진다.

이메일은 특수문자 목록을 직접 넣어야 해서 패턴이 길어진다. 특수문자 목록은 `string.punctuation`에서 볼 수 있다.

```python
import string

# list(string.punctuation)
string.punctuation
```

```text
'!"#$%&\'()*+,-./:;<=>?@[\\]^_`{|}~'
```

```python
# Email 주소만 추출 해서 출력 - 계정@도메인
# p = re.compile(r"[a-z0-9A-Z-.!#]+@[a-z0-9A-Z-.!#]+")
p = re.compile(r"[a-z0-9!#$%&'*+/=?^_`{|}~-]+(?:\.[a-z0-9!#$%&'*+/=?^_`{|}~-]+)*@(?:[a-z0-9](?:[a-z0-9-]*[a-z0-9])?\.)+[a-z0-9](?:[a-z0-9-]*[a-z0-9])")
result = p.findall(info)
print(result)
```

```text
['kjs@gmail.com', 'pys.abc@gmail.com', 'lmy-abc@naver.com', 'ksh@daum.net', 'ojy@daum.net']
```

> **보충** 긴 패턴은 이메일 형식 표준(RFC 5322)을 단순화한 널리 쓰이는 정규식이다. 안의 `(?:...)`는 **캡처하지 않는 그룹**이다. 일반 `( )`를 쓰면 `findall`이 전체 매칭 대신 그룹 내용만 돌려주는데(아래 그룹핑에서 나온다), `(?:...)`는 묶기만 하고 캡처하지 않아서 `findall`이 전체 이메일을 그대로 돌려준다.

## 문자열 변경: `sub`, `subn`

| 함수 | 하는 일 | 반환 |
|---|---|---|
| `sub(바꿀문자열, 대상, count=0)` | 패턴과 일치하는 부분을 바꾼다. count로 바꿀 개수 지정 (기본: 전부) | 바뀐 문자열 |
| `subn(바꿀문자열, 대상, count=0)` | sub와 같다 | (바뀐 문자열, 바뀐 개수) |

```python
txt = "   오늘은       목요일            입니다.                     "

p = re.compile(r" +")  # r"a+" " +" 공백 1개 이상.   \s+ 공백문자(" ", \n, \t)
result = p.sub(" ", txt)
print(txt)
print(result.strip())
```

```text
   오늘은       목요일            입니다.                     
오늘은 목요일 입니다.
```

```python
result2 = p.subn(" ", txt)
print(result2)
```

```text
(' 오늘은 목요일 입니다. ', 4)
```

```python
result3 = re.sub(r" +", " ", txt).strip()
print(result3)
```

```text
오늘은 목요일 입니다.
```

공백 덩어리 4곳이 공백 하나로 바뀌었고, 양 끝의 공백 하나는 `strip()`으로 지운다. 지난 글 전처리의 "중복 공백 축소"가 이 한 줄이다.

## 그룹핑: 패턴 안의 하위 패턴

- 패턴 일부를 **소괄호**로 묶어 하위 그룹을 만든다
- 매칭된 패턴의 일부를 다시 쓰거나, 전체 중 일부 속성만 꺼낼 때 쓴다
  - 예) 전화번호 "지역번호-국번-번호"에서 국번만 꺼내기
- `(\d{4})/([01]\d)/([0123]\d)` → (년도)/(월)/(일)

```python
txt = """tel)010-2323-3232
tel)02-323-9999
tel)031-233-4841
tel)010-1112-3344"""
print(txt)
```

```text
tel)010-2323-3232
tel)02-323-9999
tel)031-233-4841
tel)010-1112-3344
```

그룹 없이 찾으면 국번을 꺼내려고 `split`을 해야 한다.

```python
p = re.compile(r"0\d{1,2}-\d{3,4}-\d{4}") # 0\d{1,2} : 0다음에 숫자1 또는 2개
result = p.finditer(txt)

for tel in result:
    print(tel, tel.group(), tel.group().split("-")[1], sep=", ")
```

```text
<re.Match object; span=(4, 17), match='010-2323-3232'>, 010-2323-3232, 2323
<re.Match object; span=(22, 33), match='02-323-9999'>, 02-323-9999, 323
<re.Match object; span=(38, 50), match='031-233-4841'>, 031-233-4841, 233
<re.Match object; span=(55, 68), match='010-1112-3344'>, 010-1112-3344, 1112
```

그룹으로 묶으면 `group(번호)`로 바로 꺼낸다. `group(0)`은 전체다.

```python
# grouping을 이용해서 국번만 조회
# 패턴 "( 1 )-( 2 )-( 3 )"
p = re.compile(r"(0\d{1,2})-(\d{3,4})-(\d{4})") # 0\d{1,2} : 0다음에 숫자1 또는 2개
result = p.finditer(txt)
for value in list(result)[:2]:
    print("전체 text:", value.group(), value.group(0))
    print("1번 하위그룹:", value.group(1))
    print("2번 하위그룹:", value.group(2))
    print("3번 하위그룹:", value.group(3))
    print("--------------------")
```

```text
전체 text: 010-2323-3232 010-2323-3232
1번 하위그룹: 010
2번 하위그룹: 2323
3번 하위그룹: 3232
--------------------
전체 text: 02-323-9999 02-323-9999
1번 하위그룹: 02
2번 하위그룹: 323
3번 하위그룹: 9999
--------------------
```

그룹 안에 그룹을 넣을 수도 있다. 번호는 **여는 괄호 순서**로 매긴다.

```python
# ( 1 )-(2 ( 3 )-( 4 ))
p = re.compile(r"(0\d{1,2})-((\d{3,4})-(\d{4}))")
result = p.finditer(txt)
for tel in list(result)[:2]:
    print(tel.group(1))
    print(tel.group(2))
    print(tel.group(3))
    print(tel.group(4))
    print("-----------------")
```

```text

2323-3232
2323
3232
-----------------
02
323-9999
323
9999
-----------------
```

```python
txt = "2020/10/13 22:32:23"
# 1((2 )/(3 )/(4 )) 5((6 ):(7 ):(8 ))
result = re.finditer(r"((\d{4})/(\d{2})/(\d{2})) ((\d{2}):(\d{2}):(\d{2}))", txt)
for v in result:
    print(v.group())
    for i in range(1, 9):
        print(i, v.group(i))
```

> **보충** 노트북에서는 `print(v.group(1))` … `print(v.group(8))`을 여덟 줄로 썼다. 여기서는 번호를 같이 보려고 반복문으로 바꿨다.

패턴에 그룹이 있으면 `findall`은 전체 매칭이 아니라 **그룹들의 튜플**을 돌려준다.

```python
txt = "2020/10/13 22:32:23"
# 1((2 )/(3 )/(4 )) 5((6 ):(7 ):(8 ))
result = re.findall(r"((\d{4})/(\d{2})/(\d{2})) ((\d{2}):(\d{2}):(\d{2}))", txt)
result
```

```text
[('2020/10/13', '2020', '10', '13', '22:32:23', '22', '32', '23')]
```

### 패턴 안에서 하위 그룹 참조: `\번호`

`\번호`는 "그 번호 그룹이 매칭한 문자열과 **같은** 문자열"을 뜻한다.

```python
txt = "010-1111-1111, 010-1234-5678, 010-3333-3333, 010-2222-0987"

# 국번과 번호가 같은 전화번호를 조회.
p = re.compile(r"0\d{1,2}-(\d{3,4})-\1")  #\1 -> 1번 하위그룹과 같은 값
result = p.finditer(txt)
for tel in result:
    print(tel)
```

```text
<re.Match object; span=(0, 13), match='010-1111-1111'>
<re.Match object; span=(30, 43), match='010-3333-3333'>
```

### 매칭된 결과의 일부분만 바꾸기: `\g<번호>`

`sub`의 바꿀 문자열 안에서 `\g<번호>`는 그 그룹이 찾은 문자열을 그대로 넣는다.

```python
info ='''김정수 kjs@gmail.com 801023-1010221   
박영수 pys.abc@gmail.com 700121-1120212
이민영 lmy-abc@naver.com 820301-2020122
김순희 ksh@daum.net 781223-2012212
오주연 ojy@daum.net 900522-1023218
'''
```

```python
# 주민번호 뒤 6자리를 가리기(masking)
p = re.compile(r"(\d{6}-[1-8])\d{6}") # 나올 부분을 subgroup으로 묶는다.
result = p.sub(r"\g<1>######", info) 
# 변환할 문자열을 만들때 "\g<1>" 1번 subgroup으로 찾은 문자열을 그대로 나오게한다.
print(result)
```

```text
김정수 kjs@gmail.com 801023-1######   
박영수 pys.abc@gmail.com 700121-1######
이민영 lmy-abc@naver.com 820301-2######
김순희 ksh@daum.net 781223-2######
오주연 ojy@daum.net 900522-1######
```

```python
# 이름을 masking  # 김순희 -> 김**
p2 = re.compile(r"([가-힣])[가-힣]{2,}")
result2 = p2.sub(r"\g<1>**", result)
print(result2)
```

```text
김** kjs@gmail.com 801023-1######   
박** pys.abc@gmail.com 700121-1######
이** lmy-abc@naver.com 820301-2######
김** ksh@daum.net 781223-2######
오** ojy@daum.net 900522-1######
```

**그룹 참조 정리**

| 어디서 | 문법 | 쓰임 |
|---|---|---|
| 패턴 안 | `\번호` | `r'(\d{3}) \1'`처럼 같은 값이 반복되는 패턴 |
| Match 객체 | `match.group(번호)` | 찾은 결과에서 일부 꺼내기 |
| `sub()`의 바꿀 문자열 | `\g<번호>` | 찾은 일부를 살리면서 바꾸기 (마스킹) |

## Greedy와 Non-Greedy (Lazy)

수량자는 기본적으로 **Greedy(탐욕적)**로 동작한다. 가능한 한 많은 문자를 매칭한다.

| | Greedy (기본) | Non-Greedy (Lazy) |
|---|---|---|
| 동작 | 패턴을 만족하는 **가장 긴** 문자열 | 패턴을 만족하는 **가장 짧은** 문자열 |
| 문법 | `*`, `+`, `{m,n}` | 수량자 뒤에 `?`: `*?`, `+?`, `{m,n}?` |
| `<.+>` vs `<.+?>` on `<div>Hello</div>` | `<div>Hello</div>` | `<div>` |

```python
tag = "<div><a href='url'>Hello</a></div>"
# p = re.compile(r"<.+>") # greedy(기본방식)
p = re.compile(r"<.+?>") # non-greedy (수량사?)  <[^/].+?>: 닫는태그는 제외
result = p.findall(tag)
print(len(result))
result
```

```text
4
```

```text
['<div>', "<a href='url'>", '</a>', '</div>']
```

여는 태그와 닫는 태그 4개를 각각 찾았다. 주석의 `<[^/].+?>`로 바꾸면 `/`로 시작하는 닫는 태그가 빠져 여는 태그 2개만 남는다.

```python
# 보충: 세 패턴 비교
for pat in [r"<.+>", r"<.+?>", r"<[^/].+?>"]:
    print(f"{pat:10}", re.findall(pat, tag))
```

```text
<.+>       ["<div><a href='url'>Hello</a></div>"]
<.+?>      ['<div>', "<a href='url'>", '</a>', '</div>']
<[^/].+?>  ['<div>', "<a href='url'>"]
```

```python
p = re.compile(r"<.+>") # greedy(기본방식)
p = re.compile(r"<.+?>") # non-greedy (수량사?)
p.sub("", tag)
```

```text
'Hello'
```

Non-Greedy로 태그를 하나씩 지우면 내용만 남는다. Greedy였다면 문자열 전체가 한 덩어리로 매칭돼서 빈 문자열이 된다. 전처리의 HTML 태그 제거가 이 방식이다.

## 전방·후방 탐색 (Lookahead / Lookbehind)

특정 패턴의 **앞이나 뒤의 조건을 확인**하되, **그 조건 부분은 매칭 결과에 넣지 않는** 기법이다.

| 종류 | 문법 | 의미 | 예 → 결과 |
|---|---|---|---|
| 긍정 전방 | `xxx(?=패턴)` | 뒤에 패턴이 **오는** xxx | `\d+(?=원)` on `1000원, 2000달러` → `1000` |
| 부정 전방 | `xxx(?!패턴)` | 뒤에 패턴이 **오지 않는** xxx | `\d+(?!원)` → 강의 자료에는 `2000` |
| 긍정 후방 | `(?<=패턴)xxx` | 앞에 패턴이 **있는** xxx | `(?<=@)\w+` on `user@example.com` → `example` |
| 부정 후방 | `(?<!패턴)xxx` | 앞에 패턴이 **없는** xxx | `(?<!\$)\d+` on `$1000, 2000원` → 강의 자료에는 `2000` |

```python
info1 = """TV 30000원 30개
컴퓨터 32000원 50개
모니터 15000원 70개"""

p = re.compile(r"\d+(?=원)")
p.findall(info1)
```

```text
['30000', '32000', '15000']
```

"원" 앞의 숫자만 찾고 "원"은 결과에 들어가지 않았다. 개수(30, 50, 70)는 뒤에 "개"가 와서 빠진다.

```python
info2 = """TV $30000 30개
컴퓨터 $32000 50개
모니터 $15000 70개"""

p2 = re.compile(r"(?<=\$)\d+")
p2.findall(info2)
```

```text
['30000', '32000', '15000']
```

`$` 뒤의 숫자만 찾았다. `$`는 메타 문자(문자열 끝)라 `\$`로 escape한다.

### 보충: 부정 탐색과 백트래킹

강의 자료의 부정 탐색 예시들을 실제로 돌려 보면 적혀 있는 결과와 다르게 나온다.

```python
# 보충: 강의 자료 예시 그대로 실행
examples = [
    (r"\d+(?!원)",       "1000원, 2000달러",    "2000"),
    (r"\w+(?!\.txt)",    "file.txt readme.md",  "file, readme, md"),
    (r"(?<!\$)\d+",      "$1000, 2000원",       "2000"),
    (r"(?<!un)\w+able",  "comfortable, unable", "comfortable"),
]
for pat, s, expected in examples:
    print(f"{pat:16} 자료: {expected:18} 실제: {re.findall(pat, s)}")
```

```text
\d+(?!원)         자료: 2000               실제: ['100', '2000']
\w+(?!\.txt)     자료: file, readme, md   실제: ['fil', 'txt', 'readme', 'md']
(?<!\$)\d+       자료: 2000               실제: ['000', '2000']
(?<!un)\w+able   자료: comfortable        실제: ['comfortable', 'unable']
```

원인은 **백트래킹**이다. `\d+(?!원)`이 "1000원"에서 1000을 잡으면 뒤가 "원"이라 실패한다. 그러면 정규식 엔진은 포기하지 않고 `\d+`를 한 글자 줄여 "100"을 다시 시도한다. "100" 뒤는 "0"이지 "원"이 아니니 조건을 통과해서 "100"이 매칭된다. 나머지도 같은 이유다.

- `\w+(?!\.txt)`: "file"이 실패하면 "fil"로 줄여서 통과한다. "txt"도 뒤에 ".txt"가 없으니 매칭된다
- `(?<!\$)\d+`: "\$1000"의 1은 앞에 `$`가 있어 실패하지만, "000"은 앞이 "1"이라 통과한다
- `(?<!un)\w+able`: "unable"의 **시작 위치** 앞에는 ", "가 있지 "un"이 있는 게 아니라 통과한다

의도대로 하려면 **줄여서 다시 맞추는 길을 막아야** 한다.

```python
# 보충: 의도대로 고친 패턴
fixed = [
    (r"\d+(?![\d원])",     "1000원, 2000달러"),    # 뒤에 숫자도 오지 않게: 줄여서 맞추기 차단
    (r"\b\w+\b(?!\.txt)",  "file.txt readme.md"),  # 단어 경계까지 통째로
    (r"(?<![\$\d])\d+",    "$1000, 2000원"),       # 앞에 숫자도 없게: 중간부터 시작 차단
    (r"\b(?!un)\w+able",   "comfortable, unable"), # 단어 시작에서 un으로 시작하지 않는지 확인
]
for pat, s in fixed:
    print(f"{pat:18} {re.findall(pat, s)}")
```

```text
\d+(?![\d원])       ['2000']
\b\w+\b(?!\.txt)   ['txt', 'readme', 'md']
(?<![\$\d])\d+     ['2000']
\b(?!un)\w+able    ['comfortable']
```

`\b\w+\b(?!\.txt)`는 아직 "txt"(확장자 부분)가 남는다. "파일명.확장자" 단위로 다루려면 `\b[\w.]+\b`로 파일명 전체를 먼저 잡은 뒤 `endswith(".txt")`로 거르는 편이 읽기도 쉽다. 부정 탐색은 백트래킹과 만나면 직관과 다르게 동작하니, 결과를 꼭 실행해서 확인한다.

## 정리

- 정규 표현식은 **메타 문자 + 리터럴**로 패턴을 만들어 문자열을 검색·추출·변경한다. 패턴은 raw string(`r"..."`)으로 쓴다
- `match`는 시작에서, `search`는 전체에서 **첫 번째** 결과를, `findall`/`finditer`는 **모든** 결과를 찾는다
- `sub`로 바꾸고, `( )` 그룹으로 일부를 꺼내거나(`group(n)`) 살리면서 바꾼다(`\g<n>`). 패턴에 그룹이 있으면 `findall`은 그룹 튜플을 돌려주니 묶기만 할 때는 `(?:...)`를 쓴다
- 수량자는 기본이 Greedy다. HTML 태그처럼 짧게 끊어야 할 때는 `+?`, `*?`를 쓴다
- 전방·후방 탐색은 조건만 확인하고 결과에는 넣지 않는다. 부정 탐색은 백트래킹 때문에 일부만 잘라 매칭될 수 있다
