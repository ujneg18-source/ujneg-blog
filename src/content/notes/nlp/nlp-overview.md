## 이 글에서 다루는 것

- 자연어와 형식 언어, 자연어 처리란
- 자연어 처리의 두 축: 이해와 생성
- 자연어 처리의 문제 영역: 분류, 검색·질의응답, 번역, 요약, 생성, 정보 추출, 챗봇, 음성
- 자연어 처리의 단계: 수집 → 전처리 → 표현 → 모델링 → 후처리
- 텍스트 전처리의 주요 단계와 도구

딥러닝 시리즈까지는 숫자(표, 이미지)를 입력으로 받았다. 자연어 처리는 입력이 글자다. 그래서 "글자를 어떻게 숫자로 바꾸느냐"가 이 시리즈 전체를 관통하는 질문이 된다.

## 전체 흐름 한눈에 보기

```text
#DEEP => 특징 추출기(Linear/cnn/grn/lstm) + 분류기(linear)


# <단어를 나누는 과정 + 전처리하는 과정>
# tokenize =>konlp

# <특성추출>
# TF-IDF/DTM : 모델링(ml만 사용하는 것은 아님 )
# <특성추출, 자연어처리>
# Word Embedding(Word2vec, Fast text)
# RNN - LSTM, GRN + 순차데이터(time-step)

# Ex. 분류(감성분분류): Rnn(LSTM)-> Linear

# (encoder-decorder) = seq2seq
# EX. 챗봇, 번역 => 입력=>이해하는 모델(RNN) + 생성하는 모델 (RNN)  
# EX. 이미지 => 입력=>이해하는 모델(CNN) + 생성하는 모델 


# 멀티모달(다양한 입력값을 받는 주고)
```

이 메모가 시리즈의 목차와 거의 같다.

| 단계 | 하는 일 | 이 시리즈에서 다루는 것 |
|---|---|---|
| 나누기 + 전처리 | 문장을 토큰으로 자르고 정리한다 | 정규 표현식, 형태소 분석기(KoNLPy, Kiwi), Subword 토크나이저 |
| 특성 추출 (통계) | 단어 빈도로 문서를 벡터로 만든다 | DTM(Bag of Words), TF-IDF |
| 특성 추출 (임베딩) | 단어를 의미를 담은 벡터로 만든다 | Word2Vec, FastText |
| 순차 데이터 모델 | 단어 순서(문맥)까지 반영한다 | RNN, LSTM, GRU |
| 분류 | 특징 추출기 + 분류기 | LSTM → Linear 감성 분석 |
| 생성 | 이해하는 모델 + 생성하는 모델 | Seq2Seq 챗봇, Attention, Transformer |

> **보충** 메모의 "GRN"은 **GRU**(Gated Recurrent Unit)다. LSTM을 단순화한 순환 신경망으로, RNN 글에서 같이 다룬다.

## 자연어와 자연어 처리

- **자연어(natural language)**: **인간이 일상적으로 쓰는 언어**. 한국어, 영어, 일본어, 중국어처럼 역사적·사회적 과정을 거쳐 자연스럽게 만들어진 언어다
- **형식 언어(formal language)**: **사람이 설계한 규칙에 따라 인공적으로 정의한 언어**. 프로그래밍 언어(C, Python), 수식 언어(논리식, 정규식)가 대표적이다

**자연어 처리(NLP, Natural Language Processing)**는 자연어를 컴퓨터가 이해하고, 분석하고, 생성하게 만드는 기술과 연구 분야다. **사람이 쓰는 언어**와 **컴퓨터가 처리할 수 있는 표현** 사이를 잇는 다리 역할을 한다.

- 사람의 언어로 된 텍스트나 음성을 컴퓨터의 입력으로 받아들이게 한다
- 자연어에 담긴 의미, 의도, 감정, 구조를 분석하고 추론하게 한다
- 컴퓨터가 자연어로 답변하거나 문서를 생성하게 한다

### 두 축: 이해와 생성

```text
이해와 생성으로 나뉨
이해: 긍정/부정 등 어휘를 파악
생성: 답변, 번역, 요약 등 생성
둘의 전처리 방식이 다름
```

| | 이해 (Understanding) | 생성 (Generation) |
|---|---|---|
| 목표 | 글의 내용을 컴퓨터가 "이해했다"고 볼 수 있을 만큼 구조적으로 **표현**한다 | 목적과 조건에 맞는 자연스러운 문장이나 문서를 **만든다** |
| 예 | 주제 파악, 질문 의도 파악, 감정 분석, 의미역 분석, 개체 인식 | 자동 요약, 번역문 생성, 챗봇 답변, 스토리·뉴스·코드 생성 |
| 주로 쓰는 토큰화 | 형태소 단위 | 서브워드 단위 |

최근에는 딥러닝과 LLM(Large Language Model)이 발전하면서, 이해와 생성을 하나의 모델 안에서 같이 다루는 경우가 많아졌다.

> **보충** 메모의 "둘의 전처리 방식이 다름"은 아래 전처리 단계에서 다시 나온다. 이해 쪽(감성 분석 등)은 조사나 어미를 떼어 내고 핵심 형태소만 남겨도 되지만, 생성 쪽은 모델이 조사와 어미까지 다시 써야 하므로 원문을 빠짐없이 복원할 수 있는 서브워드 토큰화를 쓴다.

## 자연어 처리의 문제 영역

| 영역 | 무엇을 하나 | 예 |
|---|---|---|
| **문서·텍스트 분류** | 텍스트를 미리 정한 카테고리 중 하나 이상으로 분류 | 스팸 필터링, 뉴스 카테고리 분류, 감성 분석(긍정·부정·중립) |
| **정보 검색** | 대규모 문서에서 질의(query)와 가장 관련 있는 **문서를 찾는다** | 웹 검색 엔진 |
| **질의응답** | 문서나 지식베이스를 바탕으로 질문에 대한 **정확한 답을 찾거나 생성한다** | FAQ 자동 응답, 사내 문서 QA |
| **기계 번역** | 한 언어 문장을 다른 언어로 변환 | 언어 구조, 문맥, 문화 지식을 모두 고려해야 해서 난이도가 높다. 딥러닝 이후 성능이 크게 올랐다 |
| **요약** | 긴 문서를 짧게 줄인다 | 뉴스, 논문, 보고서 요약 |
| **텍스트 생성** | 조건이나 프롬프트에 따라 새 문장을 만든다 | 스토리·시나리오, 이메일·보고서 초안, 코드 생성 |
| **정보 추출** | 텍스트에서 **구조적 정보**를 뽑는다 | 개체명 인식(NER), 관계 추출, 이벤트 추출 |
| **의미 분석** | 문장의 의미를 이해하고 표현한다 | 의미 역할 분석, 어휘 의미 분석(중의성 해소) |
| **대화 시스템·챗봇** | 사용자와 자연어로 대화하며 답하거나 작업을 수행한다 | FAQ 챗봇, 예약 도우미, 상담 자동화 |
| **음성 관련** | 음성 인식(ASR/STT), 음성 합성(TTS) | 인식된 텍스트를 이해하고 응답을 만드는 부분이 NLP의 몫이다 |

몇 가지는 조금 더 풀어 둔다.

- **정보 검색 vs 질의응답**: 둘 다 전체 정보에서 원하는 정보를 찾는다는 점은 같다. 정보 검색은 **관련 있는 문서를 찾는 것**, 질의응답은 **정확한 답을 내는 것**에 초점이 있다
- **개체명 인식(NER, Named Entity Recognition)**: 개체명은 고유한 의미를 가진 명사나 명사구다. 사람 이름, 지명, 기관명, 제품명, 날짜, 금액 등을 찾아낸다
- **관계 추출**: "A가 B의 CEO이다" 같은 관계를 뽑는다. **이벤트 추출**은 "누가, 언제, 어디서, 무엇을 했다" 같은 사건 정보를 뽑는다
- **의미 역할 분석**: "철수/가 사과/를 먹었다"에서 철수 = 행위자(Agent), 사과 = 피행위자(Patient)처럼 각 구성요소의 역할을 정한다
- **어휘 의미 분석**: "배가 고프다"의 배가 탈것·과일·신체 부위 중 무엇인지 가린다
- **대화 시스템**은 의도 파악(intent detection), 대화 상태 추적(dialog state tracking), 응답 생성(response generation) 등 여러 문제를 결합해 만든다

## 자연어 처리의 단계

시스템마다 세부 단계와 이름은 조금씩 다르지만 전형적인 흐름은 다음과 같다.

![Text to Vector 개요](/images/nlp/fig-text-to-vector-outline.png)

### 1. 데이터 수집

- 모델을 학습시킬 데이터를 확보한다. 이렇게 모은 자연어 데이터셋을 **말뭉치(Corpus)**라고 한다
- 공개 데이터, 웹 크롤링, 로그 데이터, 문서 스캔 + OCR, 데이터베이스의 텍스트, 음성 파일·통화 녹음·동영상에서 추출

### 2. 전처리

**원시 텍스트를 모델이 다루기 좋은 단위와 형태로 바꾼다.** (아래 "텍스트 전처리"에서 자세히)

- 텍스트 정제 및 정규화: 특수문자, 불필요한 공백, HTML 태그, URL, 이모티콘 처리, 오타·띄어쓰기 교정, 형태소 분석으로 같은 의미의 단어 통일 (말했다, 말하면, 말하기 → 말하다)
- 불용어(Stopwords) 제거, 품사 기반 필터링
- 토큰화(Tokenization): 텍스트를 의미 있는 작은 단위(토큰)로 나눈다

### 3. 표현(표현 학습)

전처리와 토큰화를 마친 텍스트를, 의미를 나타낼 수 있는 숫자(Vector)로 바꾼다. **표현(representation)** 또는 **임베딩(embedding)** 단계라고 부른다.

| 방식 | 예 | 이 시리즈 |
|---|---|---|
| 통계 기반 표현 (전통적 방법) | Bag-of-Words, TF-IDF, n-gram | Text to Vector(1) |
| 분산 표현 (distributed representation) | Word2Vec, GloVe, FastText | Text to Vector(2) |
| 딥러닝 언어 모델 표현 | RNN, Transformer 계열(BERT, GPT)의 contextualized word embedding | RNN과 LSTM 이후 |

목적은 텍스트를 벡터 공간의 점(또는 점의 시퀀스)으로 나타내서, 뒤의 분류·생성·추론 모델이 쓸 수 있게 하는 것이다.

```text
# 토큰화와 임베딩은 다름
# 토큰화는 어휘사전을 만드는 과정 (int로 어휘를 분류-어떤 의미부여x) => 레이블 하는 과정 ex 원핫인코딩같이
# 임베딩은 벡터값으로 의미를 설정
```

| | 토큰화 | 임베딩 |
|---|---|---|
| 결과 | 토큰마다 정수 번호(id). `"영화" → 37` | 토큰마다 실수 벡터. `37 → [0.12, -0.8, ...]` |
| 의미 | 번호는 이름표일 뿐, 37과 38이 비슷하다는 뜻이 없다 | 비슷한 단어가 가까운 벡터가 되도록 학습한다 |
| 비유 | 머신러닝의 Label Encoding | 학습되는 Feature |

### 4. 모델링 및 추론

표현된 입력으로 문제를 푸는 핵심 모델이 동작한다.

- **분류**: 문서 분류, 감성 분석 → 머신러닝 분류 모델, 딥러닝 분류기
- **순차 레이블링**: 품사 태깅, 개체명 인식, 의미역 분석 → RNN, LSTM, Transformer 같은 시퀀스 모델
- **생성**: 번역, 요약, 대화 응답 → 인코더–디코더 Seq2Seq 구조, GPT 계열 생성 모델
- 딥러닝 모델은 대부분 **표현 학습 모델과 추론 모델을 하나로 묶어** 같이 학습시킨다

### 5. 후처리 및 출력

모델 출력을 사람이 이해하기 좋은 형태로 정리한다.

- 분류 결과: 확률에 임계값 적용, 레이블 번호를 사람이 읽을 이름으로 변환
- 추출 결과: 중복 개체 제거, 날짜 형식 통일, 주소 표기 정규화
- 생성 결과: 문법 오류, 길이, 금지어 필터링

## 텍스트 전처리

**전처리(preprocessing)**는 현실에서 모은 원시 텍스트를 기계 학습 알고리즘이나 언어 모델이 다루기 좋은 형태로 바꾸는 일련의 과정이다.

원시 텍스트에는 이런 것들이 섞여 있다.

- 오타, 반복 문자, 과도한 이모티콘: `ㅋㅋㅋㅋㅋㅋ`, `ㅠㅠㅠㅠ`, `대박이에요요요`
- HTML이나 XML 태그
- URL, 이메일, 전화번호, @아이디, 해시태그: `https://...`, `user@example.com`, `@someone`, `#자연어처리`
- 광고성 문구나 메타 정보
- 띄어쓰기 오류와 중복 공백: `"안녕하세요오늘날씨좋네요"`

이 중 분석에 불필요하거나 방해가 되는 부분은 제거하거나 치환하되, **텍스트의 의미 정보는 최대한 보존하는 것**이 목표다.

### 전처리의 주요 단계

1. **기본 정규화(Basic normalization)**: **텍스트를 일관된 형태로 통일하는 모든 작업**
   - 양쪽 공백 제거, 중복 공백 축소: `"안녕       하세요"` → `"안녕 하세요"`
   - 필요하면 대소문자 통일(영어가 섞인 경우)
   - 반복 문자 정규화: `"ㅋㅋㅋㅋㅋㅋ"` → `"ㅋㅋㅋ"` 또는 제거, `"!!!!!"` → `"!"`
   - 숫자 표현 통일: `"1,000원"`과 `"1000원"`
   - 어간/표제어 추출(stemming/lemmatization): "가다, 가고, 갔다"를 하나로 통일
     - 표제어(lemma): 기본 사전형 형태
     - 어간: 활용할 때 변하지 않는 부분. (보다, 보니, 보고의 **보**)
2. **패턴 기반 노이즈 제거**: HTML 태그 제거, URL·이메일·전화번호를 제거하거나 `<URL>`, `<EMAIL>`로 치환, 광고성 문구나 메타 데이터 제거
3. **띄어쓰기 교정**: 한국어는 띄어쓰기 오류가 잦아서 자동 교정기로 보정한다
4. **문장 분리(sentence segmentation)**: 문단이나 문서를 문장 단위로 나눈다. 구두점 기반으로 나누거나, 형태소 정보와 규칙을 쓰는 한국어 전용 문장 분리기를 쓴다
5. **토큰화(tokenization)**: 각 문장을 **토큰(token)의 시퀀스**로 바꾼다
   - 토큰은 **텍스트를 의미 있는 최소 단위로 쪼갠 조각**이다
   - 단위는 단어, 형태소, 서브워드, 문자, 자모 등 여러 가지다
   - 한국어 **이해** 문제에는 보통 **형태소 단위**, 텍스트 **생성**에는 보통 **서브워드 단위**를 쓴다
6. **추가 작업**
   - 불용어(stopwords) 제거: 조사, 접속사처럼 **자주 나오지만 의미 분석에는 별로 기여하지 않는 단어**를 뺀다
   - 품사 기반 필터링: 명사, 동사, 형용사 같은 주요 품사만 남긴다

```python
# 보충: 1~2단계를 정규 표현식으로 해 보면
import re

text = "  <b>대박이에요요요</b>!!!!!   ㅋㅋㅋㅋㅋㅋ 자세한 건 https://example.com 참고  "
text = re.sub(r"<[^>]+>", "", text)            # HTML 태그 제거
text = re.sub(r"https?://\S+", "<URL>", text)   # URL 치환
text = re.sub(r"(.)\1{2,}", r"\1\1", text)      # 같은 글자 3번 이상 → 2번
text = re.sub(r"\s+", " ", text).strip()        # 중복 공백 축소, 양쪽 공백 제거
print(text)
```

```text
대박이에요요!! ㅋㅋ 자세한 건 <URL> 참고
```

> **보충** 반복 문자 정규화는 "몇 번까지 남길지"가 정하기 나름이다. 위처럼 2번으로 줄이면 `"요요"`가 남고, 1번으로 줄이면 `"ㅋ"`처럼 감정의 강도가 사라진다. 감성 분석에서는 `ㅋㅋ`와 `ㅠㅠ`가 오히려 중요한 단서라 지우지 않는 경우도 많다. 전처리는 "깨끗하게"가 아니라 "문제에 맞게"가 기준이다.

### 전처리 도구

- **정규 표현식(regular expression)**: 패턴 기반 정제와 토큰화에 유용하다. 다음 글에서 다룬다
- 정규 표현식만으로는 한계가 있어서 전문 라이브러리를 같이 쓴다

| 언어 | 라이브러리 |
|---|---|
| 한국어 | [KoNLPy](https://konlpy.org/ko/latest/), [KiwiPiePy](https://github.com/bab2min/kiwipiepy), [soynlp](https://github.com/lovit/soynlp) |
| 영어 | [NLTK](https://www.nltk.org/), [spaCy](https://spacy.io/) |

## 정리

- 자연어 처리는 사람의 언어를 컴퓨터가 **이해**하고 **생성**하게 하는 분야다. 둘은 목표가 달라 전처리와 토큰화 방식도 달라진다
- 문제 영역은 분류, 검색·질의응답, 번역, 요약, 생성, 정보 추출, 대화 시스템 등으로 나뉜다
- 처리 흐름은 **수집 → 전처리 → 표현 → 모델링 → 후처리**다. 딥러닝에서는 표현과 모델링을 한 모델로 같이 학습한다
- **토큰화**는 텍스트를 잘라 번호를 붙이는 것이고, **임베딩**은 그 번호에 의미를 담은 벡터를 주는 것이다
- 전처리는 정규화, 노이즈 제거, 띄어쓰기 교정, 문장 분리, 토큰화, 불용어 제거 순으로 진행하며, 무엇을 지울지는 풀려는 문제에 따라 정한다
